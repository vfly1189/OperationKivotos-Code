## 1. 서사

### 1.1 문제 상황

단일 Sector 방식이었다 (서 있는 섹터만 켜고, 벗어나면 끔).

- **경계선에서 몬스터가 갑자기 사라지거나 나타난다**
  - 사라짐: 몬스터를 끌고 경계를 넘으면, 쫓아오던 몬스터가 눈앞에서 사라진다
    → "몬스터를 언제 회수해야 하나?"에 대해, 위치·전투 여부를 안 보고 섹터가 꺼지는 즉시 회수해서 생긴 문제
  - 나타남: 새 섹터에 들어서는 순간, 경계 근처 몬스터가 한꺼번에 생긴다
    → 섹터 단위로 켜기 때문에 생긴 문제 (판정 단위의 문제)
- **비용이 과다하게 쓰인다**
  - 유지 비용: 섹터가 크면 화면에 안 보이는 영역까지 연산한다 (켜진 몬스터의 약 90%가 화면 밖)
  - 순간 비용: 섹터가 바뀌는 순간 그 섹터 몬스터 전부를 한 프레임에 생성·회수한다 (최대 119마리)
- **섹터를 사람이 직접 지정한다**
  - 신규 맵이나 크기 조정 시 에디터에서 구역·스포너 소속을 일일이 다시 맞춰야 한다
  - 경계 문제를 인접 섹터로 풀면 인접 표까지 관리해야 한다

### 1.2 원인 진단

- **사라짐은 "판정 방식"이 아니라 "회수 규칙"의 문제다.**
  → 어떤 방식이든 공통으로 몬스터 규칙을 둔다: **교전 중이면 유지, 교전이 끝나면(리쉬 귀환 포함) 회수.**
- **나머지(나타남 · 유지 비용 · 순간 비용 · 사람 작업)는 섹터 크기 하나에 묶여 있다.**
  → 작게 나누면 비용은 줄지만 경계와 인접 표가 늘고, 크게 하면 반대. 크기 조정으로는 못 푼다.
  → 이 묶음을 푸는 정도에 따라 후보 6개가 나오고, ⑤를 엔진에 맡기는 구현 하나(⑦)를 더한다.

| # | 방식 | 묶음을 어떻게 다루나 |
|---|---|---|
| ① | Sector — 서 있는 곳만 | 묶인 그대로 (기준선) |
| ② | Sector + 인접 | 크기는 그대로, 경계만 한 칸 밀어냄 |
| ③ | 스포트라이트 3×3 (칸 20m) | 구역을 자동 격자로, 플레이어 칸 ± 1칸 |
| ④ | 스포트라이트 5×5 (칸 10m) | 칸을 작게, 창을 크게 → 원에 근사 |
| ⑤ | 거리 (켜기 20m / 끄기 25m) | 구역 없음. 켜기·끄기 반경을 따로 조절 |
| ⑥ | 스포트라이트 + 거리 (5×5 · 칸 13m) | 창은 후보 찾기, 판정은 ⑤의 원 → 결과는 ⑤와 같고 선택 비용만 다름 |
| ⑦ | CullingGroup 거리 밴드 (밴드 20 / 25m) | 판정은 ⑤와 같고, 계산을 Unity 엔진 컬링 단계에 맡김 → 결과는 ⑤와 같고 선택 비용 · 반응 시점(1프레임 지연)만 다름 |

⑦′ CullingGroup 가시성(화면 절두체로 켜고 끔)은 구현하지 않는다. 시뮬레이션에서 화면 가장자리 0.2m 등장 · 떨림 23% · 감지 거리 15m 안 부재 51%로 탈락 조건에 걸리고, 구를 키워도 떨림은 남는다(가시성에는 히스테리시스가 없음) — 근거 [CullingGroup_Comparison.pdf](CullingGroup_Comparison.pdf). 가시성의 쓸모는 존재 층이 아니라 틱 층(화면 밖 몬스터 갱신 줄이기)이라 이 비교 밖, Phase 5 이후 후속.

### 1.3 문제 해결

- 7개 방식 비교 (⑦′ 가시성은 시뮬레이션으로 탈락 처리)
  - 측정 전에 시뮬레이션으로 예측을 먼저 박제한다 (4절)
  - 비용 측정: 선택 비용 / 몬스터 1마리 비용 분해(행동 트리 · NavMesh · 애니메이터 · HP바) × 활성 수 / 전환 스파이크 / 필요 풀 크기
  - 현상 측정: 화면 안 등장·소멸 횟수 / 끌고 온 몬스터 소실 횟수 / 경계 떨림 횟수 + Before·After 영상
- 탈락 조건을 통과하고 모든 항목에서 앞선 방식을 채택해 구현한다 (측정 후 확정)
  - 예상: 판정은 거리 방식. 스포너가 아주 많아지면 스포트라이트+거리(⑥) 또는 CullingGroup(⑦)으로 구현만 교체 — 둘 중 무엇인지는 Phase 4에서
  - Sector가 맞는 경우도 명시: 구역이 실제 벽·게임플레이 단위와 일치하는 곳
- 한계: 싱글 플레이, 맵 1개, 측정 환경

## 2. 판정 방법

점수 합산은 쓰지 않는다. 가중치가 결론을 정하고, 치명적 결함이 점수에 묻히기 때문이다.

1. **탈락 조건** — 하나라도 못 넘으면 비용과 상관없이 탈락
2. **우열 확인** — 통과한 방식끼리, 모든 항목에서 같거나 나은 방식이 있는지
3. **점수(필요할 때만)** — 2에서 장단점이 엇갈릴 때만. 가중치와 "1등이 바뀌는 가중치 범위"를 함께 공개

| 탈락 조건 (제안 — Phase 0에서 확정) | 기준 |
|---|---|
| 화면 안 등장·소멸 | 0회 |
| 끌고 온 몬스터 소실 | 0회 |
| 경계 떨림 | 하네스 왕복 구간에서 0회 |
| 풀 확장 | 풀 200에서 0회 |
| 프레임 시간 p99 | 기준선(①) 측정 후 수치 확정 |

예측 문장 (측정 후 맞았는지 대조):
- P1. 선택 비용은 7개 모두 μs 단위로, 결론에 영향이 없다.
- P2. 유지 비용은 평균 활성 수에 비례한다 → ② > ① > ③ > ④ > ⑤ = ⑥ = ⑦.
- P3. 전환 스파이크는 ①②가 가장 크고(한 걸음 119), ⑤⑥⑦이 가장 작다(34).
- P4. 풀 200을 넘는 방식은 ②뿐이다(최대 295).
- P5. 경계 떨림은 ⑤⑥⑦만 0이고, ③④가 가장 크다(11~14% · 사각형 창은 켜는 선 = 끄는 선). Sector ①②도 2%. ③ · ④의 수치는 청크 원점에 따라 8~41% · 12~29%로 흔들리지만, 어느 원점에서도 0보다 크다([Chunk_Origin.pdf](Chunk_Origin.pdf)).
- P6. ⑤와 ⑥은 모든 프레임에서 활성 집합이 같다.
- P7. ①은 화면 안 소멸이 생겨 탈락한다.
- P8. 섹터 균형은 Sector의 순간 비용만 줄이고(119 → 85) 유지 비용은 못 줄인다(평균 71 → 73).
- P9. 두 배치에서 7개 방식의 순위가 같다(평균 활성 · 순간 비용 동일, 최대 활성 · 떨림은 역전 없음) → 결론은 배치에 의존하지 않는다.
- P10. ⑦의 활성 집합은 1프레임 지연을 빼면 ⑤와 같다(두 배치 · 1,311 지점 전부 같음).
- P11. ⑦′ 가시성은 탈락한다 — 가장자리 여유 0.2m · 떨림 23 / 22% · 감지 거리 안 부재 51 / 49%. (구현 안 함, 시뮬레이션 근거)
- P12. 스포너 23개에선 ⑤ · ⑥ · ⑦의 선택 비용 차이가 결론에 영향 없다. 10,000개에선 ⑤만 비례 증가하고 ⑥ · ⑦은 평평하다.
- P13. 존재를 ⑤로 정해도 켜진 몬스터 33마리 중 화면에 닿는 스포너 몫은 14마리(44%), 실제 화면 안은 3.5마리 → 틱 층 절감 여지(이 비교 밖).
- P14. 청크 원점을 어디에 두든 ③ · ④는 ⑤보다 평균 활성이 많고, 스파이크가 크거나 같고, 떨림이 0보다 크다. 원점에 따라 갈리는 건 ③과 ④ 사이뿐(원본에서 ③ 떨림 < ④는 원점 400개 중 305개).

## 5. 단계

```
Phase 0  사전 작업 ── 결정 고정 · 공통 규칙 · 이음새 · 계측 · 하네스 · 예측 · Before
Phase 1  몬스터 1마리 비용 환산 ── 시간 분해 · 스폰 분해 · 메모리
Phase 2  정책 구현 ── ②~⑦ + ⑤=⑥=⑦ 동등성 검증
Phase 3  메인 측정 ── 7개 × 3회 (+ 선택: 밀도 ×1.5 · ×2)
Phase 4  선택 비용 경계 ── ⑤ · ⑥ · ⑦, 스포너 23 → 10,000
Phase 5  판정 · 채택 구현 ── 탈락 → 우열 → 적용 · 예측 대조 · After
Phase 6  결과 문서 · 포트폴리오
```

측정: 개발 빌드 · 그림자 끔 · 정책 7개 × 3회 무인 하네스(`58f32b83`) → [Policy_Result.pdf](Policy_Result.pdf) · [Worklog_2026-10-09.md](Worklog_2026-10-09.md) 8~10절.

### 8.1 채택 — ⑤ Distance (켜기 20m · 끄기 25m) + 교전 유지

- **탈락 조건**: 통과는 ⑤⑥⑦뿐. ①(화면 안 등장 9 · 떨림 136) ②(떨림 114 · 풀 확장 187) ③(떨림 77) ④(떨림 19) 탈락 — 칸 · 섹터 경계에 히스테리시스가 없다.
- **우열**: ⑤⑥⑦은 살아 있는 몹 24.4~24.7 · dt p50 1.50 · p99 2.54ms로 모든 시간 지표가 3회 편차 안 → 구별 불가. 셋 중 **구현 · 디버깅이 가장 단순한 ⑤**. ⑥은 격자 · 후보 캐시가, ⑦은 카메라 렌더링 의존 · 1프레임 지연이 더 붙을 뿐 얻는 게 없다.
- **비용을 정하는 것**: 판정 방식이 아니라 살려 두는 몹 수 — dt p50 = 1.307ms + 7.57μs × 살아 있는 몹(r = 0.9998). 판정 비용은 프레임당 1~8μs로 몬스터 1마리(7.57μs) 이하.
- **교전 유지**: 21회 모두 끌고 온 몹 소실 0, 실행 끝 유예 0 → 공통 규칙으로 확정.

### 8.2 하지 않기로 한 것과 근거

| 항목 | 근거 | 다시 할 조건 |
|---|---|---|
| Phase 4 선택 비용 경계 (스포너 1천 ~ 1만) | ⑤ 판정 = 스포너당 약 48ns · 할당 없음 · 선형 → 1만 개도 약 0.5ms. 클라이언트가 들고 있는 스포너 수는 스트리밍 단위로 제한되므로 1만은 현실 시나리오가 아님 | 한 지역에 로드되는 스포너가 수천 개 이상 · 판정이 프레임당 0.1ms를 넘을 때 → ⑥(격자) 또는 ⑦로 **구현만 교체**(정책 이음새 그대로) |
| 반경 스윕 (14 ~ 25m) | 비용은 반경을 줄일수록 단조 감소(몹 수 ∝ 반경²)라 최적점이 없고, 몹 수 × 7.57μs로 예측 가능. 20m → 15m 절약 약 0.08ms(프레임 1.50ms의 5%). 20m는 탈락 조건 전부 통과 · 스폰 순간 화면 안 0. 하한은 측정이 아니라 설계로 정해짐(감지 15m + 슬롯 퍼짐 5.5m) | 감지 거리 · 카메라 시야를 바꿀 때 하한 재계산 |
| 프레임 스폰 예산 | 거리형의 한 프레임 최대 스폰은 스포너 하나(17마리) → 그 프레임 4.2~7.9ms(대부분 ~5ms). 스폰 1마리 ≈ 프레임 +0.184ms → 한 프레임 약 28마리까지 예산(6.94ms) 안 | 밀도를 올려 한 프레임 스폰이 약 25마리를 넘을 때(칸형 34마리 프레임 = 7.2~10.8ms가 실측 근거) |
| 1-2 몬스터 1마리 시간 분해 · 1-4 메모리 | 채택 결정에 필요한 "1마리 단가"는 1-1로 확보 | 몬스터 단가 자체를 줄이는 작업(틱 층 · LOD)을 시작할 때 |
