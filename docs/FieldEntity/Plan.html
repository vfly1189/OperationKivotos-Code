Operation Kivotos · 필드 엔티티 관리 · 02 실행 계획서

몬스터를 먼저 잡고, 그 위에서 비교한다

범위는 일반 필드(로아 필드형) 하나. 메인은 Sector vs 거리(B), 확장은 B vs 청크+거리(C). 그 전에 몬스터·풀·스포너가 성해야 측정이 방식의 차이를 잰다.

① 트랙의 구조 — 무엇을 무엇 위에 쌓는가

② 로드맵 — 약 6주 (1인 · 순차 기준)

주황 = 토대(몬스터) · 보라 = 측정 인프라 · 파랑 = 메인(B) · 초록 = 확장(C). 각 막대는 추정 최대치 기준. 6·7은 둘 다 5 이후라 순서를 바꿔도 된다.

1. 몬스터 코드 현재 상태 — 2026-09-28 점검

생명주기 계약을 코드에 옮기던 미커밋 작업이 절반 들어가 있다. 정의는 있고 호출이 없다. (정적 읽기 기준 · 플레이 미확인)

③ 스폰 · 회수 흐름 — 지금 vs 목표 지금은 끊겨 있음

현재 코드는 훅 본문을 목표 위치로 옮겼지만 배선(호출)이 없어서 CTS가 영영 만들어지지 않는다. Phase 1은 배선이 핵심이다.

#증상 (추정)위치
W1원거리 몹 활성화 시 NRE (프리웜 Create() 경로 포함)Ranged.OnEnable
W2사망 처리 NRE → 죽은 몹이 풀로 회수되지 않음Base.HandleDeadState
W3공격 시 NRE — TryCast(..., _monsterCts.Token)AR · RL · Tank
W4타겟을 못 얻어 전부 Idle — 파티 구독이 OnSpawn에만NormalMonsterController
W5HP바 중복 생성 — OnEnable마다 생성, 반납은 사망 경로에만. 구역 이탈로 회수된 몹을 다시 꺼내면 하나 더Normal.OnEnable
W6WaitNode.Reset()이 _duration까지 0으로 — 구조와 상태를 섞음 (보스 전용 · 현재 무증상)BTNode.cs
Before 영상은 생명주기를 고친 뒤에 찍는다 경계 소실은 몬스터 코드가 아니라 Sector 정책(DespawnMonsters가 산 몹을 즉시 회수)에서 나온다. Phase 1~4는 그 정책을 건드리지 않으므로 현상은 남아 있다 → Phase 4 하네스 경로로 녹화, 마감은 Phase 5 전. After와 같은 경로라 나란히 비교할 수 있다. 미커밋 리팩터는 방향이 계약과 일치하므로 버리지 않고 Phase 1의 출발점으로 쓴다.

2. 토대 — Phase 0 ~ 3

기존 점검(Lifecycle L0~L7 · Issues S1~S6 · M1~M7 · 풀 30 vs 119)을 여기서 전부 소화한다. 각 Phase에 수치로 된 완료 조건을 둔다.

Phase 0 — 박제반나절 · 지금
  • 예측 박제 → 03_Predictions.md — 메인·확장 지표 각각의 방향과 대략의 크기. 구현 후에 쓰면 예측이 아니다
Phase 1 — 몬스터 생명주기 완성3~4일 · L0~L7 · W1~W6 · M1 · M3 · M7
  • 1-1 IPooledMonster 계약 — OnSpawn(SpawnContext) / OnDespawn()
  • 1-2 SpawnContext 실체화 — 스탯 데이터 · 스폰 위치 · 소유 스포너 (읽기 전용)
  • 1-3 스폰 배선 — ResourceManager에 activate: false 이음새 → MonsterFactory가 SetStat → OnSpawn → SetActive(true). 필드·일반던전·보스던전이 전부 팩토리를 지나므로 한 곳
  • 1-4 회수 배선 — Pool.Push 안에서 OnDespawn(). 사망·구역 이탈·씬 정리가 한 경로 (Release()는 만들지 않음)
  • 1-5 훅 정리 — HP바 생성은 OnSpawn(base 뒤 · 토큰 가드)·반납은 OnDespawn / agent 켜기를 Normal.OnEnable로 올리고 1프레임 대기 제거 / 탄약은 OnSpawn만 / Start·_initialized 삭제
  • 1-6 BT Reset() — 구조는 유지, 상태만 (WaitNode._duration 보존)
  • 1-7 확인 — 프리팹 루트 active(프리웜 성립) · 스폰 포인트 NavMesh 위 · HP바 생성 경로
완료 조건 — 같은 인스턴스 3회 재사용해도 1회차와 동작 동일 · 구역 10회 왕복 후 HP바 수 = 파티 구독자 수 = 활성 몬스터 수 · NRE 0 · [PoolLeak] 0 · 던전 두 곳 회귀 없음
Phase 2 — 풀 용량 · 관측1일 · Prerequisites 1.2
  • 2-1 CreatePool 수량을 하드코딩 30 대신 스포너 데이터 집계값으로 (RL 최대 119)
  • 2-2 Pop이 즉석 Create()하면 개발 빌드 경고 [PoolGrow]
  • 2-3 HP바 프리팹에 Poolable — 생성·파괴가 풀 경로로
완료 조건 — 전 구역 순회 중 [PoolGrow] 0. 이 조건을 만족한 측정만 채택
Phase 3 — 스포너 정리 · 포인트 레코드2~3일 · S1~S6 · 방식 F
  • 3-1 명시적 활성 상태 (activeInHierarchy 대용 제거) · 3-2 CTS를 인스턴스 동일성으로 · 3-3 점유 검사 + 생성 직후 토큰 재검사
  • 3-4 포인트별 상태 레코드 — 살아있음 / 재등장 예정(절대 시각) / 비어있음. 몬스터 인스턴스와 독립, 소유 범위는 디스폰 완료까지
  • 3-5 데이터 방어 · 조용한 continue에 경고 · 3-6 리스폰 지터
완료 조건 — 스포너가 Activate() / Deactivate()만으로 켜고 꺼짐 · 꺼진 스포너에서 부활 0 · 한 포인트 2마리 0 · 꺼졌다 켜져도 리스폰 타이머 유지. Sector와 B가 똑같이 이 API를 부르므로, 여기가 비교의 이음새다.
⚠ Deactivate()는 산 몹을 즉시 회수하는 현재 동작 유지 — 전투 유예는 Phase 5. 미리 넣으면 Before 영상을 못 찍는다.

3. 비교 — Phase 4 ~ 8

토대가 끝나면 판정 정책만 갈아끼우며 잰다.

Phase 4 — 판정 정책 추상화 · 측정 하네스 · 기준선1주
  • IActivationPolicy — Sector / Distance(B) / ChunkDistance(C), 런타임 전환
  • 고정 경로 자동 주행 — 웨이포인트 + 고정 속도. 몹을 끌고 경계를 넘는 구간 포함 (경계 소실을 재현해야 하므로)
  • 수집: 활성 수 타임라인 · 화면 밖 비율 · 스폰/디스폰 횟수 · 스폰 1회 평균 비용 · 프레임당 최대 스폰 · p50/p99 · 경계 소실 이벤트 · [PoolGrow]
  • 기존 계측(MetricsHotkeys · 개발 빌드 로그) 재사용
완료 조건 — 현재 Sector로 같은 경로 3회, 지표 편차가 방식 간 예상 차이보다 충분히 작음 (하네스 자체 검증) · Before 영상 녹화 (몹 끌고 경계 통과 구간 · Phase 5 전 마감)
Phase 5 — B + 안정화1주
  • CullingGroup에 스포너 구체 등록 · 진입/이탈 반경 · onStateChanged로 켜기/끄기 (갱신 조건 API 확인 필요)
  • 히스테리시스 · 프레임당 스폰 예산
  • 움직이는 몬스터: 전투 중 유지 → 리쉬 복귀 → 스포너 상태 따름 → 유예 상한
Phase 6 — 메인 측정 S vs B2~3일
  • 같은 경로·같은 빌드, 정책만 전환
  • 그림 ④ + 지표 표 + 예측 대조 (틀린 곳은 틀렸다고)
  • After 영상
Phase 7 — C + 스케일 테스트3~4일
  • 격자 + 외접 사각형 셀 조회 → 후보만 거리 판정
  • 동등성 검증 먼저 — 매 프레임 B·C 활성 집합 일치
  • 합성 N = 23 / 100 / 1k / 10k — 목표 규모가 아니라 교차점 탐색용
  • 곡선 3개로 네이티브 vs 알고리즘 분리 (그림 ⑤)
Phase 8 — 결론 · 문서 · 슬라이드3~4일
  • 실제 맵을 B로 전환, C 전환 조건 N 기록
  • Sector 볼륨: 삭제 / 게임플레이 구역
  • 04_Result.md · 슬라이드 4~5장

④ 메인 — 예상 모양 측정 전

두 곡선 사이 면적 = 화면 밖에서 켜 둔 낭비. 계단의 높이 = 진입 스파이크.

⑤ 확장 — 예상 모양 측정 전

작은 N에선 격자 관리비로 C가 불리. 교차점 ② 이전이면 "현실 규모에선 B"가 결론이 된다.
