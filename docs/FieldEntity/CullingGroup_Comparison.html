CullingGroup을 넣은 7개 방식 비교 예측

Unity CullingGroup을 7번째 후보로 넣어 기존 6개와 같은 시뮬레이션(두 배치 · 655m 경로 · 1,311 지점)으로 다시 계산했다. 플레이 측정이 아니라 측정 전 예측이다.

요약
  • CullingGroup은 판정 "방식"이 아니라 판정을 계산해 주는 "엔진 기능"이다. 무엇으로 판정하느냐(거리 밴드 / 가시성)에 따라 두 가지로 쓸 수 있고, 결과가 정반대다.
  • ⑦ 거리 밴드로 쓰면 결과가 ⑤ 거리와 같음다 (두 배치 · 1,311 지점 전부). 밴드 {20, 25}를 두고 band 1에서 이전 상태를 유지하면 히스테리시스가 된다. 차이는 결과가 아니라 계산 위치뿐 — C# 루프 대신 엔진 컬링 단계, 메인 스레드엔 바뀐 스포너만 콜백.
  • ⑦′ 가시성으로 쓰면 탈락한다. 화면 가장자리 0.2m에서 나타나고 사라지며, 1m 왕복 떨림 23%, 감지 거리 15m 안 몬스터가 꺼져 있는 지점이 경로의 51%. 구를 키워도 떨림은 남는다(가시성에는 히스테리시스가 없다).
  • CullingGroup의 제자리는 존재 층이 아니라 틱 층이다. ⑤로 켠 평균 33마리 중 화면에 닿는 스포너 몫은 14마리, 실제 화면 안은 3마리. 나머지는 행동 트리 · 애니메이터를 줄여도 안 보인다. 지금 몬스터 프리팹 3종의 Animator는 AlwaysAnimate.
  • 결론 순서는 그대로다. 존재 판정은 ⑤ = ⑥ = ⑦ 공동 1위(결과 동일). 셋 중 선택은 규모 · 제약으로 — 스포너 23개에선 ⑤가 가장 단순하고, ⑦은 카메라 의존 · 1프레임 지연 · 게임 밖 측정 불가를 대가로 큰 규모에서 메인 스레드 비용을 줄인다.

CullingGroup이 하는 일

Unity 매뉴얼 “CullingGroup API” · 스크립트 레퍼런스 “SetBoundingDistances” 기준 (2026-10-07 확인)

항목API이 비교에서의 의미
입력SetBoundingSpheres — 배열을 복사하지 않고 참조몬스터가 아니라 스포너(고정 · 23개)를 등록 → 인덱스 = 스포너, 안 바뀜
거리 밴드SetBoundingDistances + SetDistanceReferencePoint. 거리를 정수 밴드로 양자화. 구 중심이 아니라 구 표면까지. 마지막 값 너머는 강제로 비가시{20, 25} → band 0 켬 · 1 유지 · 2 끔 = ⑤의 켜기 · 끄기. 반경 0 구면 ⑤와 같은 거리
가시성targetCamera 하나의 절두체 + 정적 오클루전만. 동적 오클루더는 반영 안 함쿼터뷰라 사실상 "화면 사다리꼴에 닿느냐"
갱신 시점카메라 컬링이 실행될 때만 계산. 바뀐 구만 onStateChanged, 폴링은 QueryIndices · GetDistance결과가 렌더링 단계에서 나옴 → 스폰은 다음 Update로 = 1프레임 지연
히스테리시스문서에 없음밴드 두 개 사이를 "유지"로 읽어 직접 만든다. 가시성에는 만들 수 없다(그룹 두 개 필요)
매뉴얼 사례보이는 개체만 군중 시뮬 · 스폰 포인트가 안 보일 때 스폰 · 거리별 LOD 행동 · 1만 개 이상 근접 감지"보이는 것만 시뮬" · "LOD 행동" = 틱 층, "근접 감지" = 존재 층
같은 API, 두 가지 사용법 (같은 축척)
왼쪽은 플레이어 기준 원 두 개로 켜고 끈다(⑤와 같은 모양). 오른쪽은 화면 사다리꼴 기준으로 켜고 끈다 — 화면이 감지 거리 원보다 훨씬 작아서, 공격해 와야 할 몬스터 상당수가 존재하지 않는다.

이음새(ActivationPolicy)에 끼우면 — 스케치, 구현 아님
public class CullingGroupActivation : ActivationPolicy
{
    CullingGroup _group; BoundingSphere[] _spheres; int[] _ids;   // 배열은 참조됨 → 필드로 붙잡아 둔다
    readonly HashSet<int> _on = new();
    readonly Queue<CullingGroupEvent> _pending = new();

    public override void Init(ActivationLayout layout)
    {
        // _spheres = 스포너 중심 · 반경 0 (⑤와 같은 거리)   _ids[i] = 스포너 id
        _group = new CullingGroup { targetCamera = Camera.main };
        _group.SetBoundingSpheres(_spheres);
        _group.SetBoundingSphereCount(_spheres.Length);
        _group.SetBoundingDistances(new[] { 20f, 25f });          // band 0 켬 · 1 유지 · 2 끔
        _group.onStateChanged = e => _pending.Enqueue(e);        // 컬링 중 호출 → 여기서 스폰하지 않는다
    }

    public override void SelectSpawners(Vector3 pos, IReadOnlyCollection<int> current, HashSet<int> result)
    {
        _group.SetDistanceReferencePoint(pos);                     // 이번 위치는 다음 컬링에 반영 (1프레임)
        while (_pending.TryDequeue(out var e))
        {
            if (e.currentDistance == 0) _on.Add(_ids[e.index]);
            else if (e.currentDistance == 2) _on.Remove(_ids[e.index]);   // 1이면 그대로 = 히스테리시스
        }
        result.UnionWith(_on);
    }
    // 씬 Clear 때 _group.Dispose()
}
첫 프레임 초기 상태가 콜백으로 오는지는 확인 필요 — 안 오면 Init 직후 GetDistance로 한 번 동기화. 바뀐 게 없으면 콜백 0회.

이 트랙에서의 위치비교 이후

틱 층은 존재 판정 비교의 변수가 아니다(어느 방식에나 똑같이 얹힌다). 비교를 오염시키지 않도록 Phase 5 채택 이후로. Phase 1 "1마리 비용 분해"에서 애니메이터 · 행동 트리 몫이 크게 나오면 다음 작업 근거가 된다.
