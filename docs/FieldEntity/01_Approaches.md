# 01. 방식 지도 (텍스트 요약)

> 도식 원본: [Approaches.pdf](Approaches.pdf). 이 파일은 검색·diff용 요약이다.

## 0. 층 구조 — 이 문서의 좌표계

| 층 | 묻는 것 | 반경 |
|---|---|---|
| ① 틱 (품질) | 얼마나 자주 생각하나 | 가장 좁다 (≈화면) |
| ② 존재 (GameObject) | 씬에 오브젝트가 있나 | 화면 ~ 화면×2 |
| ③ 로드 (에셋·지형) | 메모리에 올라와 있나 | 훨씬 넓다 |
| ④ 레코드 (데이터) | 상태·타이머가 기록돼 있나 | 맵 전체, 항상 |

A~D는 **② 존재 층**의 반경을 정하는 방식이라 서로 경쟁한다. E~H는 다른 층이라 겹쳐 쓴다.

## 1. 현재 — Sector

트리거 진입 시 그 구역 스포너 전부 켜고 이전 구역 전부 끔.
문제: 경계 소실 · 단위 > 화면 · 저작 노가다 · 진입 스파이크.
패치(인접 켜기 / 전투 중 유지)는 경계 소실만 막는다.

## 2. A — 균일 청크(격자)

`셀 = (⌊x/S⌋, ⌊z/S⌋)`. 플레이어 주변 3×3 켬, 5×5 밖에서 끔(히스테리시스).

- 풀어줌: 저작 0 · 조회 O(1) · 셀 = 로드/저장 단위로 재사용 · 이웃 탐색·광역 판정에도 재사용
- 남김: 셀 크기 S 딜레마(작으면 churn, 크면 낭비) · 네모 활성 영역(대각 1.41배) · 셀 경계에서 여러 셀 동시 전환

## 3. B — 거리

스포너마다 플레이어와 거리. 진입 반경에서 켜고 이탈 반경에서 끔(히스테리시스).
Unity `CullingGroup` (`SetBoundingSpheres` / `SetBoundingDistances` / `SetDistanceReferencePoint` / `onStateChanged`).

- 풀어줌: 경계 자체가 없음 · 고정 쿼터뷰에선 반경 = 화면 · 저작 0 · 스폰이 자연 분산
- 남김: 전수 검사 O(N) · 팝인 · 자유 카메라에선 거리 ≠ 시야 · 밀집에 무력
- **등록 대상은 스포너** (정적, 개수 1/10~1/20)

## 4. C — 청크 + 거리

Broad(청크: 반경의 외접 사각형이 걸치는 셀만 후보) → Narrow(거리 + 히스테리시스).
판정 비용 O(k). 청크는 **로드 층**, 거리는 **존재 층**에 쓰면 층 구조가 자연스럽게 나온다.

솔직한 단서: 스포너 23개면 전수 검사도 공짜. 값어치는 CPU보다 **맵이 커져도 구조 불변** + **격자 재사용**.
참고: 마인크래프트(렌더 거리 ≠ 시뮬레이션 거리), UE World Partition(격자 셀 + 스트리밍 소스 반경).

## 5. 어느 방식이든 남는 것 — 움직이는 엔티티

스포너는 범위 밖인데 끌려온 몬스터는 플레이어 옆. → **소유권 규칙**으로 푼다.

- 정적인 것(스포너·NPC) = 공간으로 판정
- 움직이는 것(몬스터) = 자기 상태로 판정: 전투 중이면 유지 → 전투 이탈 시 리쉬 복귀 → 도착 후 스포너 상태 따름 → 유예 상한 N초

## 6. 기타 방식

| | 방식 | 층 | 한 줄 | 언제 |
|---|---|---|---|---|
| D | 쿼드트리 | 존재 | 빽빽한 곳만 잘게 쪼갬 | 밀도 편차가 극단적인 맵 |
| E | 중요도/LOD 틱 등급 | 틱 | 끄지 않고 느리게. 위상 오프셋. 생각은 가끔, 움직임은 매 프레임 | 밀집. 다른 방식 위에 겹쳐서 |
| F | 가상화 (레코드/오브젝트 분리) | 레코드 | 존재 ≠ 오브젝트. 리스폰 시각은 절대 시각 | 어떤 방식이든 같이 필요. 영속 상태의 기반 |
| G | 지역 스트리밍 | 로드 | 반오픈월드=맵 단위 분리+로딩, 오픈월드=격자 셀 스트리밍 | 맵을 통째로 못 올릴 때 |
| H | 인카운터 · 웨이브 예산 | 존재 | 동시 생존 상한 · 프레임당 스폰 제한 · 풀 선워밍 | 좁은 아레나 대량 |
| — | 서버 AOI | (참고) | 서버가 있으면 존재 층은 서버로, 품질 층만 클라에 | 이 프로젝트 범위 밖 |

## 7. 장면별 조합

| 층 | 연속 필드 (우리 맵) | 좁은 아레나 대량 | 오픈·반오픈월드 |
|---|---|---|---|
| ① 틱 | E (실측 후 필요 시) | **E + 일괄 업데이트** | E |
| ② 존재 | **C + 소유권 규칙** | H | C (로드된 지역 안) |
| ③ 로드 | 맵 통째 | 던전 통째 + 풀 선워밍 | **G** |
| ④ 레코드 | F (스포너 소유) | 거의 불필요 | F (영속) |

굵은 칸 = 그 장면의 주 전장.

## 8. 제안과 다음에 정할 것

**제안**: 존재 층을 C(청크 + 거리)로. Sector의 네 문제를 판정 기준 교체로 한 번에 제거하고,
격자를 리소스(로드)·어빌리티(광역 판정)와 잇는 고리로 쓴다. 규모상 B로 먼저 만들고 청크를 나중에 끼우는 순서도 가능.

**정할 것**
1. 범위 — 연속 필드는 확정. 좁은 아레나 대량(H+E)을 추가할지 / 오픈월드(G)는 설명만 할지
2. 반경 — 진입/이탈 (후보 35m / 50m), 셀 크기 S (후보 ≈25m)
3. 등록 단위 — 스포너 확정? NPC·채집물도 같은 등록기에?
4. 움직이는 몬스터 규칙 — 전투 유예 · 리쉬 · 상한 N초
5. 레코드 분리 — `BaseMonsterController[]` → 포인트별 상태 레코드, 리스폰 타이머 절대 시각
6. Sector의 운명 — 삭제 / 게임플레이 구역(지역명·BGM·필드 보스)으로 역할 변경
7. 측정 — 기존 계측(활성 수·히칭·팝인)을 가져올지

**선행 조건**: 생명주기 계약(OnSpawn/OnDespawn 미배선) · 풀 프리워밍 부족. 방식을 바꾸면 스폰/디스폰이 잦아지므로 이 둘이 먼저.
