## 1. SectorManager 정리

- `SectorManager`는 이미 죽은 코드였다 — `Sector` 등록 줄이 주석이라 사전이 늘 비어 있었고, 판정은 ① `SectorActivation` 정책이 대신하고 있었다. BenchmarkTester F1/F2도 아무 동작을 안 했다.
- 삭제: `SectorManager.cs`(+ 폴더 · meta) · `Managers.Sector` · 주석 처리된 `_sector.OnUpdate()`
- `Sector`는 영역(`Contains`) + 스포너 id + 기즈모만 남기고 `Managers/Core/Field/`로 이동(.meta 함께 → GUID 유지, 프리팹 참조 안 깨짐)
- F1/F2(전체 켜기 · 정책 복귀) → `ActivationManager.SetForceAll`. 정책 판정 · 그림자 로그는 계속 돌고 스포너 켜고 끄기만 덮는다. 풀면 실제 정책 집합 밖만 끈다.

## 2. 0-2 교전 유지 규칙

**규칙**: 정책이 스포너를 꺼도 교전 중인 몹은 바로 회수하지 않고 유예 목록에 둔다. 매 틱 확인해서 교전이 끝나면 회수.

- `IsEngaged` = 살아 있음 ∧ (귀환 · 추적 · 공격 · 장전 중 ∨ **대상이 감지 거리 안**)
  - 감지 거리 조건을 더한 이유: 공격 · 장전 종료 애니 이벤트가 `_state`를 Idle로 돌린 뒤 다음 행동 트리 평가까지 한 프레임 틈이 있어, 스포너 틱이 그 틈에 싸우는 몹을 회수할 수 있었다.
- 막는 것은 "정책이 끄는 회수"뿐. 사망 회수는 그대로.
- 유예 중 슬롯은 Alive 유지 → 스포너가 다시 켜져도 중복 스폰 없음.
- 귀환 이벤트가 아니라 매 틱 상태 확인 — "집 2m 안에서 싸우다 대상 놓침"은 귀환이 안 일어나므로.
- 누수가 없는 근거 = 리쉬(교전은 반드시 귀환으로 끝난다). 상한 = 슬롯 수.
- F3 = 리쉬 + 교전 유지 함께 끔 (Before 녹화용 — 리쉬 없이 교전 유지만 켜면 교전이 안 끝날 수 있다).
- 플레이 확인: 몹을 스포너 끄기 범위 밖까지 끌고 감 → 인지 범위를 벗어나 귀환 → 집에 도착한 뒤에야 회수.

| 파일 | 내용 |
|---|---|
| `field_{정책}[_shadow]_{시각}_frames.csv` | 프레임마다 — dt · Main Thread · 마커 9개(ProfilerRecorder 합계, μs) · 스폰/회수/유예 수 · 몹/화면 안/유예/켜진 스포너 · 메모리 |

- 마커: 정책 선택(실제/그림자) · 스포너 틱 · 스폰 4단계(풀 꺼내기 / SetStat / OnSpawn / SetActive) · 회수 · 계측 자체

- 위치: 에디터 = 프로젝트 루트 `MetricsLogs/`, 빌드 = exe 옆 `MetricsLogs/` (git 밖).
- 첫 측정에서 고친 것: 측정 경로의 `Debug.Log` 제거(교전 유예 개수 로그 삭제 — 틱에 약 170μs 섞였다 · 리쉬 귀환 로그는 `LogLeash`로 기본 끔), 화면 판정 표본에서 `Camera.main`을 프레임당 1번.

- **프레임 시간 = 1.307ms + 7.58μs × 살아 있는 몹 수** (7개 정책 평균점, r = 0.9998). 정책 간 평소 프레임 차이는 전부 "몹을 몇 마리 살려 두나"로 설명된다. 판정(선택) 비용은 1~8μs/프레임으로 무시 가능.
- **⑤ · ⑥ · ⑦은 시간으로 구별되지 않는다** — 모든 시간 지표 차이가 3회 편차 안. 셋 중 선택은 시간 외 기준(구현 · 운영)으로.
- **스폰 1회 비용은 정책과 무관**(125~141μs, ②만 풀 확장 때문에 165) — 같은 스폰 경로라 당연. 회수 66~83μs.
- **프레임 스폰 예산 재평가**: ⑤⑥⑦의 17마리 스폰 프레임은 dt p50 4.8 · 최대 6.0~7.2ms → 144fps 예산 안팎. ① 풀 꺼내기 수정 전 추정(17마리 ≈ 11.7ms)은 더 이상 맞지 않는다. ⑤⑥⑦의 6.94ms 초과 프레임 5~9개 중 스폰 · 회수가 겹친 것은 ⑦의 1개뿐이고, 최악 프레임은 계측 자체(4.8~6.7ms = 프레임 목록 용량 두 배 확장 복사)다.
- **② AdjacentSector**: 동시 생존 최대 295 > 풀 200 → 187회 런타임 Instantiate, 119마리 스폰 프레임 97ms(pop만 48ms). 풀 크기를 정책 비용에 포함해야 한다(필요 풀 295).
- **⑦ 순간이동 직후**: 하네스 시작 순간이동(settle, 분석 구간 밖)에서 ⑦만 3회 모두 화면 안 스폰 10. CullingGroup 상태는 렌더링 때 갱신돼 한 프레임 늦게 반응 → 카메라가 따라온 뒤 스폰된다. ⑤⑥은 순간이동 프레임에 바로 스폰해 카메라가 따라오기 전 위치로 화면 판정 → "화면 밖"으로 찍히지만 다음 프레임엔 보인다(측정 착시 추정). 걸어서 이동하는 구간에선 셋 다 0.
