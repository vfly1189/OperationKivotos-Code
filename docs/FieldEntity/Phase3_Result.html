2. 슬롯 상태 기계

포인트 하나 = 슬롯 하나. 런타임 상태는 필드 4개가 전부다
그림 2 · 상태 전이와 ReadyAt · Gen이 붙는 자리 (실선 = 평소, 점선 = DeActivate)
Waiting은 DeActivate에도 그대로 — ReadyAt이 알람 시각이라 꺼져 있어도 시간이 흐른다. Alive 즉시 회수는 Before(경계 소실) 재현을 위해 일부러 유지.
필드뜻바뀌는 순간
_stateWaiting · Spawning · Alive · Dying틱 · 팩토리 반환 · 사망 · 회수 · DeActivate
_readyAt이 시각부터 스폰 가능 (알람 시각)회수 시 now + respawnTime × 지터 · DeActivate로 되돌릴 때 now · 스폰 실패 시 백오프
_gen지금 유효한 주문 번호스폰 요청 시 +1 · Spawning 중 DeActivate 시 +1
_instance슬롯이 관리하는 몬스터gen이 맞는 결과가 도착하면 설정 · Detach 시 비움
ReadyAt — 카운트다운이 아니라 시각
옛 방식은 포인트마다 UniTask.Delay를 돌려 끄면 취소(놓치면 S1 · S2), 켜면 처음부터 다시 셌다. ReadyAt은 시각 하나만 적고 틱이 now ≥ ReadyAt만 비교한다. 취소할 것이 없고, 꺼진 동안에도 시간이 흐른다.
Gen — CTS 취소가 아니라 번호 비교
팩토리는 비동기라 요청과 도착 사이에 스포너가 꺼졌다 켜질 수 있다. 늦게 온 결과가 슬롯을 덮으면 S3(2마리) · S1(꺼진 곳 부활). 결과는 어차피 올 수 있다고 인정하고, 도착한 순간 gen != slot._gen이면 회수한다.

5.2 플레이에서 드러난 것 ① — 파티 준비 전에 스폰 (P1)

ArgumentOutOfRangeException ← PartyRegistry.GetCurrent ← PartyManager.GetCurrentCharacter
  ← NormalMonsterController.OnSpawn ← MonsterFactory ← SpawnerManager.SpawnAsync
그림 3 · GameScene 초기화 순서와 스폰 시점
채택 — 등록과 가동 분리
Init은 레코드만 받고, Run()은 GameScene이 CreateCharacters 뒤에 부른다. 가동 전에 온 Activate는 IsActive만 켜 두므로 신호를 잃지 않고, 가동 순간 시작 섹터가 채워진다. "필드가 준비되기 전엔 스폰하지 않는다"를 스포너가 보장.
기각 — GetCurrent()가 null 반환
예외는 사라지지만 Party.Init이 OnActiveCharacterChanged를 발생시키지 않아 그 사이 나온 몬스터는 타깃 없이 서 있게 된다. 증상만 숨김.

5.3 플레이에서 드러난 것 ② — 몬스터가 실행마다 나왔다 안 나왔다 (P2)

같은 코드로 어떤 실행은 정상, 어떤 실행은 몬스터가 보이지 않았다. 캐릭터를 바꿔도 안 나왔고 예외는 0. 임시 진단 로그([SpawnDiag])로 단계를 나눠 추적했다.

그림 4 · 진단 — "만들어지지 않았다"와 "만들어진 뒤 사라졌다"를 가르기
그림 5 · 원인 — CurrentScene이 로딩 커버를 집는다
어느 쪽이 집힐지 정해져 있지 않아 비결정적. 옛 스포너는 5초 지연 덕에 커버가 사라진 뒤 스폰해서 드러나지 않았다.
같이 해결된 것 SceneManagerEx.LoadScene의 CurrentScene?.Clear()가 커버의 Clear를 대신 불러 씬 정리(Spawner.Clear · 입력 구독 해제)가 빠질 수 있던 문제. SelectScene · NormalDungeon · BossDungeon도 같은 커버를 쓰므로 같은 위험이 사라졌다.
교훈 기존 버그가 타이밍이 바뀌면서 드러났다(P1 · P2 둘 다 "첫 스폰 즉시"가 방아쇠). 진단 로그는 요청 → 도착 → N초 뒤 생존처럼 단계별로 찍어야 "만들어지지 않았다"와 "만들어진 뒤 사라졌다"를 가를 수 있다. 진단 로그는 확인 후 전부 제거했다.
