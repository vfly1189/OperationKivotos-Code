SkillSystem 전체 구조 — 보스 · 일반몹 공용

같은 SkillSystem을 보스는 HP선 · 가중치로, 일반몹은 탄 수로 부른다 — SS는 누가 부르는지 모른다. GAS를 모티브로 언제 / 써도 되나 / 순서 / 신호 / 무엇을 / 어디에 / 결과를 층으로 나눴고, 보스 하나와 일반몹 셋이 같은 코드 위에서 에셋만 다르게 돈다.

1. 층 지도 — 층마다 아는 것이 하나

지키는 규칙

  1. 아래층은 PatternContext만 읽는다
    시전자 · 타겟 출처 · 소켓 · memo · 스탯 · 토큰 — 컨트롤러가 누구인지 모른다
  2. Event는 상속 한 번, 나머지는 조합
    위치 · 간격(PointEmitter) · 세기(DamageSpec) · 판정(HitShape)은 필드로 든다
  3. Action은 상태 가능, Event는 무상태
    Action은 한 번에 하나, Event는 겹쳐 Fire될 수 있다
  4. new DamageInfo는 Stat 안에서만
    판정하는 쪽은 HitPoint만 채운다

2. 한 패턴의 일생 — AR 공격 한 번

빨간 구간(신호)만 애니 · 타임라인에 따라 다르고, 나머지 길은 보스와 몹이 같다

단계마다 누가

  1. 고르기 → 허락 (①②)
    선택기가 SS.CanUse로 거른 뒤 확정 — SS도 같은 CanUse로 같은 프레임에 받으므로 어긋나지 않는다
  2. 순서 (③④)
    Runner가 memo를 비우고 첫 Action을 시작 — Action은 애니 CrossFade 또는 타임라인 Play
  3. 신호 (⑤)
    Receiver → SS.SendTag → 지금 Action의 OnTag(끝 태그) → Task 중 태그 · 조건이 맞는 것만 Fire
  4. 결과 (⑥)
    Event가 Fire 때 패킷 1번, PointEmitter가 점 · 간격 · 회차대로 결과를 낸다
  5. 끝 (⑦)
    끝 태그 또는 상태 종료 → 다음 Action → 마지막이면 PatternEnded, BT가 다음 판단

3. 몬스터에 붙는 방식 — 같은 SS, 다른 호출자

Base가 맡는 것 (모든 몬스터)

  1. 사망 = Health.OnDead 이벤트
    OnDeath → SS.Cancel · 콜라이더 · Death · 디스폰
  2. SS 생애
    OnSpawn ResetState · OnDespawn Cancel
  3. BuildContext()
    시전자 · 타겟 · 소켓 · 스탯 · 생애 토큰

MonsterState 해체

  1. 살았나
    Health.IsDead
  2. 행동 중
    SS.IsBusy (회전은 Pattern._faceTarget)
  3. 교전 중
    계산 — 살아 있고 귀환 · 행동 · 감지 중

5. 신호 입구 둘 — Unity 전달 방식이 둘이라서

정한 것

  1. 애니 이벤트 함수 이름은 오브젝트 안에서 유일하게
    같은 이름의 함수를 가진 컴포넌트 전부에 간다 → OnAnim… 접두사
  2. 입구는 SS 밖에
    SS가 Unity 전달 방식 · 함수 이름에 묶이지 않게 — SS는 태그만 받는다
  3. 두 입구는 하나로 합칠 수 있다
    전달 방식이 둘일 뿐 — 지금은 둘로 두고 동작 확인

6. 이관 기록 — 확장 증거

공용으로 만들려면 SS로 무엇을 올려야 했나

  1. 사망 · 생애 처리
    보스 컨트롤러 안에 있던 것을 Base로 — 몹도 같은 길
  2. ctx 조립
    BuildContext를 Base 한 곳에
  3. 애니 이벤트 신호 · 태그로 끝나는 Action
    보스는 타임라인이라 필요 없었다 — 몹의 이어지는 애니(Attack_Start → Ing → End)

9. 어느 층이 GAS에 가까운가

AbilitySystem

  1. 허락 층이 GAS에 가장 가깝다
    Required · Blocked · Grants 태그, Commit / Fire 분리
  2. 흐름이 선형 Effect 목록
    선택 · 분기 · 여러 단계를 못 담아 보스에서 막혔다(②)

SkillSystem

  1. 흐름 · 신호 · 타게팅이 GAS에 가깝다
    Action 순서 + 태그 신호 + Placement
  2. 상태 태그 게이트는 자리만
    AbilitySystem의 Required/Blocked/Grants를 가져올 자리
