데미지 파이프라인 — 누가 읽고, 누가 판정하고, 누가 계산하나

보스 장판 · 내려치기의 데미지는 네 가지 일로 나뉜다 : 공격력 읽기 · 맞았나 판정 · 데미지 계산 · 보이기. 문제는 "VFX에 콜라이더를 달까, BMC가 처리할까"가 아니라 이 네 가지를 누구에게 맡기느냐다.

1. 세 가지 방법 — 누가 무엇을 맡나

주황 문제가 생기는 칸   초록 제자리에 있는 칸

왜 ③인가

  1. ① — VFX가 로직의 주인이 된다
    이펙트마다 스크립트가 붙음 → 두 번째 보스에서 이펙트만 바꿔도 코드가 늘어남 ("코드 0줄" 깨짐)
    판정 시점이 파티클 수명 · 물리 트리거에 끌려감 (풀 재사용 때 OnTriggerEnter 재진입, 안에 서 있는 대상 처리)
  2. ② — BMC는 "언제" 층이다
    맞을 때마다 BMC로 돌아오면 BMC가 모든 Event의 결과를 알아야 함 → 층이 섞임
    판정은 여전히 VFX 콜라이더 → ①의 문제가 그대로 남음
  3. ③ — 각자 이미 있는 자리에 맡긴다
    공격력은 Stat, 판정은 Event의 부품(HitShape), 계산은 이미 하나로 모여 있는 Health, 이펙트는 보이기만

BMC는 데미지에 관여하지 않는다 — ctx에 보스 Stat을 넣어 주는 것까지만

2. 전체 흐름 — 패킹 1번, 판정은 점마다, 계산은 피격자

규칙 두 개

  1. new DamageInfo는 Stat 안에서만 만든다
    공격자 파라미터(공격력 · 배율 · 치명타)를 반영하는 곳이 한 군데 → 보스든 플레이어든 같은 입구
  2. 판정하는 쪽은 HitPoint만 채운다
    HitShape든 투사체든 패킷을 복사해서 맞은 위치만 넣고 TakeDamage — 숫자는 건드리지 않는다

3. 시간으로 보면 — 패킹은 처음 1번, 판정은 여러 번

왜 Fire 때 1번만 패킹하나

  1. 판정이 보스를 다시 찾지 않는다
    장판 틱이 도는 중에 보스가 죽거나 풀로 돌아가도 패킷은 이미 손에 있음
    지금 Health.cs:49의 damageInfo.Attacker.layer는 공격자가 사라지면 NRE → 팀 값을 패킷에 저장해서 막음
  2. 점이 48개여도 Stat 계산은 1번
    판정마다 하는 일은 복사 + HitPoint 채우기뿐
  3. "이 패턴의 세기"가 시작할 때 정해진다
    패턴 도중 버프 · 디버프가 와도 이미 나간 패턴은 그대로 — 의도한 동작

4. 그럼 콜라이더는 언제 쓰나 — 움직이는 것

투사체는 이미 이렇게 한다 — SpawnProjectiles가 시전 때 패킷을 만들어 넘김

5. 지금 코드 — ① 방식이 이미 깨진 곳

Lightning.cs

  1. 데미지가 VFX에 박혀 있음
    _damage = 10f 직렬화 값 — 보스 Attack과 무관
  2. 공격자가 번개 자신
    Attacker = this.gameObject — 누가 때렸는지가 틀어짐

GenesisAttack.cs

  1. 값을 밖에서 넣어 줘야 함
    Init(damage, attacker)를 누군가 불러야 동작
  2. 버그 이력
    하드코딩 500 — VFX가 값을 들면 이런 실수가 숨기 쉬움
