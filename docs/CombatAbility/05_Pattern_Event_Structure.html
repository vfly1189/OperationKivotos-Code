Pattern Event 구조 — 언제 · 무엇을 · 어디에 · 간격

신호(태그)가 오면 Task가 태그 + 조건으로 거르고, Event가 무엇을 한다. 점이 필요한 Event는 PointEmitter를 필드로 들고 → Placement가 어디에 → Emitter가 간격대로 돌린다. 아래층은 전부 PatternContext만 읽는다.

1. 전체 흐름

층마다 하나씩만 안다

  1. 언제 — 신호 · Task
    타임라인 TagMarker가 태그를 보내고, 현재 Action의 Task 중 태그와 조건(memo 값)이 맞는 것만 Fire
  2. 무엇을 — Event
    PatternEvent를 한 번만 상속. "점 하나에 무엇을 하나"만 쓴다
  3. 어디에 · 간격 — PointEmitter · Placement · Anchor
    상속이 아니라 필드로 조합 — 다섯 Event가 같은 부품을 쓴다

2. Event — 상속은 한 번, 위치는 조합

"한 번 때리기"와 "동심원 48번 때리기"는 같은 StrikeEvent — PointEmitter 설정만 다르다

3. PointEmitter — 간격 · 묶음

점 12개를 어떤 리듬으로 쓰느냐는 interval과 batch 두 값이 정한다.

4. Placement — 기준점 4가지 × 모양 4가지

이번에 늘어난 것

  1. Anchor.Saved
    앞 Event가 saveAs로 memo에 적은 점을 기준점으로 — 패턴 3의 "장판 중심 기준 안 / 밖"
  2. CirclePlacement.radii[]
    반지름을 여러 개 주면 동심원, 넣은 순서 = 터지는 순서 (8 → 6 → 4 → 2 = 조여 옴)
  3. PointFacing (Inherit · Outward · Inward)
    점 하나하나가 볼 쪽 — 기하라서 Placement가 정한다. 프리팹 자세 보정(_vfxEuler)만 Event에

5. 생각 중인 패턴 4개 — 전부 에셋 조립

새 코드 0줄 — Event 5개 · Placement 4개 조합과 Task 조건만으로 네 패턴이 나온다

6. 패턴 3 실행 순서 — memo와 조건이 어떻게 이어지나

분기가 Event 안에 없는 이유

  1. 고르기와 분기를 뗐다
    ChooseEvent는 memo에 적기만, 분기는 Task 조건이 — StrikeEvent 안에는 if가 하나도 없다
  2. 같은 Task 안 순서가 보장된다
    Choose · Activation · Field는 기다리는 게 없어 Fire 호출 안에서 끝남 → 뒤 Event가 memo를 바로 읽는다
  3. memo는 패턴 하나 동안만
    Runner가 하나를 들고 패턴 시작마다 비운다 — 이전 패턴의 relic · zone이 남지 않는다
