# 리소스 수명 시스템 리팩터 — 포트폴리오 핵심 요약

> Unity Addressables 위에 **수명 스코프 계층**을 얹어 상주 메모리를 회수한 리팩터.
> 상세 여정: [Journey_Full.md](./Journey_Full.md) · 도식 포함 PDF: `Portfolio_Summary.pdf`

---

## 1. 한 문장

> 리소스의 실제 수명은 5종 이상인데 표현 수단이 2개(Global/Scene)뿐이라, 애매한 것이 전부 "안전한 쪽 = Global"로 도피해 영구 상주하던 구조를, **`(key,type)` refCount 레지스트리 + 수명 스코프**로 재구축해 상주 메모리를 회수했다. **수동 Release 코드는 한 줄도 추가하지 않았다.**

## 2. 헤드라인 숫자 (진입 직후, Baseline v2 → 완료)

| 지표 | Before | After | 변화 |
|---|---|---|---|
| Global 핸들 메모리 | 513 MB | **205 MB** | **−60%** |
| 전체 합계 | 617 MB | **363 MB** | **−41%** |
| Global 단조 증가(세션) | +56 MB | **+16 MB** | **−72%** |

**대가(정직하게):** 진입 −308MB ↔ 팝업 첫 오픈 +14~20ms. **상시 부담을 일회성 지연으로 바꾼 거래.** 재오픈은 회귀 없음(~9ms).

## 3. 구조 (2버킷 → 스코프 + 레지스트리)

```
ResourceManager(파사드) → ResourceScope(수명 티켓) → ResourceRegistry(핸들 소유) → Addressables
```

**설계 3원칙**
1. 핸들 소유는 **레지스트리 한 곳** — 스코프는 티켓(`HashSet<ResourceKey>`)만. "누가 Release하나" 문제 소멸.
2. 스코프 내 중복 로드 = **refCount 1** (`HashSet.Add` 반환값). refCount = "소유한 서로 다른 스코프 수".
3. **취소 ≠ 해제** — 토큰은 기다림 중단만. 수명은 스코프 소유 → use-after-release 구조적 불가.

**수명 계층:** `Global`(영구) · `Scene`(씬) · `Party`(파티 유지, 씬 전환 생존) · `Popup`(스택 있는 동안).

## 4. 방어 질문 3종

| 질문 | 답 |
|---|---|
| **"Addressables가 이미 refCount인데 왜 위에 또?"** | Addressables refCount는 **핸들 단위 수동 짝맞추기** — 호출부가 Release를 '기억'해야 하고, 그 기억의 실패가 HP바 누수였다. 스코프는 **기억을 구조(수명 단위 자동 정산)로 대체**한 것 |
| **"본인이 만든 문제를 본인이 고친 것 아닌가?"** | 맞다, 숨기지 않는다. 2버킷은 초기 설계였고 **계측으로 한계를 발견 → 개인의 주의력이 아니라 구조로 재발 차단**. 레거시 개선은 실무의 일상, 이 프레이밍이 성장 서사 |
| **"1인 프로젝트에 오버엔지니어링 아닌가?"** | 팝업 세션 +287MB라는 측정치가 필요성을 증명. 반대로 던전 스코프·프레임 예산 스트리밍·DDOL 대공사는 **측정 근거로 제외** = 필요한 것만 했다는 증거 |

## 5. 어필 포인트 (결과물보다 방법론)

- **"측정 → 진단 → 구조 → 검증" 루프** — 각 결정에 트레이드오프 근거.
- **숫자를 믿기 전에 도구를 검증했다** — 측정 도구가 아틀라스를 ×6.8 과대 계상하던 계통 오차를 플레이 모드 교차 검증으로 발견·보정. 계측 이관 후엔 `isGlobal` 한 줄만 토글해 **단일 변수 A/B**로 도구 등가성까지 실측(512.8MB 소수점 일치).
- **계측이 기존 버그 3건을 드러냈다** — 전부 뿌리가 **"에셋 수명 ≠ 인스턴스 수명"**. "메모리가 줄었다"가 실은 누수를 못 센 결과일 수 있음을 R6에서 실증(합계 보존 = 유령이 회계에 드러남).
- **셀프 코드리뷰로 잔여 결함 2건 자가 발견·수정** — 취소 경로 유령 핸들 누수 + 아틀라스 중복 전개. 실측으로 누수 0·왕복 flat 재검증.
- **정직함** — split-brain 버그를 숨기지 않고 "과도기 구조가 만든 버그를 디버깅으로 잡았다"로 서술.

## 7. 한계 (반드시 동반)

- 메모리 **버킷별 절대값**은 에디터 측정(CPU 사본 과대 계상) — 증감·비율만 인용. 단 **총량 절대값은 개발 빌드 실측 확보**(§6), Addressables **Use Existing Build = 실제 번들**로 증감·비율은 신뢰도 "강".
- 그래픽스 드라이버 메모리는 지연 반납 특성 → 회수 판정 주 신호는 **텍스처**.
- 히치 ms는 n=1~3, 15ms 이하 차이 주장 금지.
