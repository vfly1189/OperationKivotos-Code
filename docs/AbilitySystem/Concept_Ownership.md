# AbilitySystem — 개념 정리: 무엇을 누가 소유하나 (서사 재료)

> **한 줄 요약** — 플레이어·보스·몬스터가 각자 갖고 있던 공격 코드를 **`AbilityRunner` 단일 창구**로 모아
> **쿨타임·비용 판단을 한 곳에서** 하게 했다. 실제 효과는 자주 쓰는 패턴을 **`Effect`로 정의해두고 조합**해서 만든다.
> **효과가 실제로 나가는 순간은 애니메이션 이벤트가 담당**해 타격감을 살렸다.

포트폴리오 헤드라인/면접 설명으로 그대로 꺼내 쓸 수 있는 개념 정리. 상세 구현은 [Phase1_Result.pdf](Phase1_Result.pdf).

---

## 큰 그림

```
플레이어 ┐
몬스터  ┼─▶  AbilityRunner (단일 창구)  ─▶  Effect 조합 실행
보스    ┘        └ 쿨타임 · 비용 · 태그 판단
```

전(前): "누가 쓰느냐"에 따라 공격/게이팅 코드가 **3벌**, 쿨타임 상태가 **여러 곳에 중복**.
후(後): 셋 다 같은 창구로. 새 스킬 = 코드가 아니라 **데이터(Effect) 조합**.

---

## 핵심 — "발동 타이밍"은 두 가지 뜻이다 (관심사 분리)

여기가 설명할 때 헷갈리기 쉬운 지점. "발동 타이밍"을 러너가 다 갖는 게 아니라 **둘로 갈린다**:

| 무엇 | 뜻 | 소유자 |
|---|---|---|
| **발동 자격 판단** | "지금 써도 되나?" — 쿨 끝났나 · 비용 되나 · 태그 조건 되나 | **AbilityRunner** |
| **실제 발사 순간** | "애니메이션 어느 프레임에 총알/효과가 나가나" | **애니메이션 이벤트(AbilityBeat)** |

> **자랑 포인트** — "판단은 시스템(러너)이, 타이밍은 애니메이션이." 이 역할 나눔 덕에
> ① 쿨/비용 규칙은 한 곳에서 관리되고 ② 발사가 애니 프레임에 정확히 붙어 타격감이 산다.

---

## 소유권 지도 (누가 무엇을)

| 관심사 | 소유자 | 메모 |
|---|---|---|
| 입력 (키/마우스) | PlayerController · BT(몹) | "언제 시도할지" |
| 발동 자격 (쿨·비용·태그) | **AbilityRunner** | 단일 게이트 |
| 쿨타임 **값** (예: 15초) | 데이터(CharacterDataSO) | 디자이너가 조정 |
| 쿨타임 **상태** (남은 시간) | 러너 인스턴스(캐스터별) | 같은 스킬 에셋 공유해도 안 섞임 |
| **무엇을** 할지 (효과) | **Effect 조합** (데이터) | 데미지·투사체·상태변경·범위·흐름 |
| **언제** 발사 (프레임) | 애니메이션 이벤트 | 타격감 |
| 연출 (컷신·카메라) | 애니메이션/타임라인 | 캐릭터 밖 |

한 문장 규칙: **"판단·규칙 = 시스템 / 무엇을 = 데이터 / 언제·연출 = 애니메이션."**

## 그대로 써먹을 문장들

- (한 줄) *"플레이어·보스·몬스터가 각자 갖던 공격 코드를 단일 창구로 모으고, 효과는 재사용 패턴을 조합해 데이터로 만들었다."*
- (관심사 분리) *"발동해도 되는지(쿨·비용)는 시스템이, 실제 발사 순간은 애니메이션이 갖게 나눴다."*
- (효과 조합) *"자주 쓰는 동작을 Effect로 정의해두고, 새 스킬은 코드 없이 이들을 조합해 만든다."*
- (결과) *"발동 경로 3→1, 새 스킬 = 데이터 조합(코드 0), 쿨타임 관리 코드 뭉치 삭제."*
