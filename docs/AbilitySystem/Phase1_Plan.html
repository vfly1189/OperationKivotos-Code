Operation Kivotos · Player AbilitySystem · Phase 1

게이팅 단일화 — 계획 + 명세

세 곳에 흩어진 게이트와 두 벌로 평행 존재하는 쿨 상태를 AbilityRunner 한 권위로. 쿨은 절대시각으로, 코스트만 Stat에 위임.

한 줄 요약 — 지금 세 곳(CharacterCombat 평타레이트 · CharacterStat Q/E 쿨 · AbilityRunner 쿨)에 흩어진 게이트와, 두 곳(Stat·Runner)에 평행 존재하는 쿨 상태를 AbilityRunner 한 권위로 모은다. 쿨은 절대시각(IClock)으로만 존재 → PartyManager.TickCooldowns 삭제. 코스트(에너지·궁게이지)만 Stat에 남기고 러너가 위임 호출로 소비한다.
상위 청사진: Player_Refactor_Blueprint §02·§04 · 선행: Phase0_Result.md · 범위 — Phase 1만. 발동 경로 통일(E→AbilityBeat)은 Phase 2, 컷신/Q 분리는 Phase 3. 여기선 fire 타이밍을 바꾸지 않는다.

01지금 상태 — 무엇이 어디에

게이트 3주인 · 쿨 상태 2벌 평행 · delta-tick의 우회비용.

게이트위치판단상태 소유시각
평타레이트CharacterCombat.CanAttackNow - _lastAttackTime ≥ _attackRate_lastAttackTimeTime.time
Q 쿨+궁CharacterStat.TryUseSkillQQCool≤0 AND Energy≥MaxCurrentQSkillCoolTimedelta-tick
E 쿨CharacterStat.TryUseSkillEECool≤0CurrentESkillCoolTimedelta-tick
러너 쿨+태그AbilityRunner.TryCastIsOnCooldown + Req/Blocked 태그_cooldownEnd[AbilityData]IClock.Now

중복의 핵심 — 같은 Q/E 발동이 Stat 게이트(입력 시점) 와 러너 게이트(fire 시점) 를 둘 다 통과한다. 쿨 상태가 Current*CoolTime(delta-tick)과 _cooldownEnd(절대시각) 두 벌로 평행 존재 → "이 스킬 쿨 누가 정함?"이 모호.

delta-tick의 대가 — 스왑아웃(비활성) 멤버는 CharacterStat.Update가 안 돌아 쿨이 멈춘다. 이를 메우려 PartyManager.TickCooldowns(dt)가 매 프레임 전 멤버를 대신 tick한다. 절대시각으로 가면 이 우회가 통째로 불필요.

발동 흐름 (fire 타이밍 — Phase 1에서 유지)

슬롯입력 진입점입력 시점 게이트(현재)상태 전이fire(이펙트) 시점
평타Attack_combat.CanAttack+TryAttack→ Attack애니 AbilityBeat → UseAbility(Attack,beat)
QUseSkillQ_combat.TryUseSkillQ(=Stat)→ CutScene→Q_Skill애니 AbilityBeat → UseAbility(Skill,beat)
EUseSkillE_combat.TryUseSkillE(=Stat)→ E_Skill즉발 UseAbility(Ex) (입력 시점)
게이트의 두 역할 (A) 입장(admission) — 스킬 상태로 들어갈지(입력 시점) · (B) 발사(fire) — 이펙트 실행(비트/즉발). Phase 1의 과제는 A·B 둘 다 러너가 소유하는 쿨/코스트/태그를 보게 만드는 것. fire 타이밍 자체는 안 건드린다.

02목표 설계 — 러너가 admission과 fire를 분리 소유

TryCast 한 덩이(게이트+코스트+쿨+캐스트+이펙트)를 admission(동기·부작용)과 fire(비동기·무게이트)로 쪼갠다.

2.1 AbilityRunner 새 공개 API (명세)

public class AbilityRunner
{
    // ── 판독 (부작용 없음) — UI/스펙 체크. 아무것도 소비/변경 X ──
    public bool  CanCast(AbilityData a, AbilityContext ctx);

    public float CooldownRemaining(AbilityData a);  // 남은 쿨(초). 준비되면 0
    public float CooldownDuration(AbilityData a);   // 이번 쿨 총 길이(CDR 반영값 저장 → UI 정확)

    // ── admission (동기·커밋) — 통과 시 코스트 소비 + 쿨 시작. 이펙트는 안 함 ──
    public bool Commit(AbilityData a, AbilityContext ctx);

    // ── fire (비동기·무게이트) — 캐스트타임 → 이펙트 순차 → GrantsTags try/finally ──
    public UniTask Fire(AbilityData a, AbilityContext ctx, CancellationToken token);

    // ── 편의: Commit+Fire 동시. 몬스터/보스처럼 게이트·발사가 같은 순간인 호출부용 ──
    //     기존 시그니처 유지 → BaseMonsterController 등 호출부 무변경
    public async UniTask TryCast(AbilityData a, AbilityContext ctx, CancellationToken token)
    {
        if (!Commit(a, ctx)) return;
        await Fire(a, ctx, token);
    }
}

책임 분해

  • Commit: ① 쿨 검사 → ② 코스트 검사·소비(§3) → ③ 태그 게이트(Req/Blocked) → ④ 쿨 시작(_cooldownEnd = Now + Cooldown·CDR). 하나라도 실패 시 부작용 0으로 조용히 false.
  • Fire: 캐스트타임 대기 → BuildRuntimeEffects() 순차 실행 → GrantsTags(캐스트 스코프, 예 State.Casting) try/finally 해제. 쿨/코스트/Req·Blocked 재검사 없음.
  • GrantsTags는 fire 소유(발동 지속), RequiredTags/BlockedTags는 admission 소유(입장 판정).

2.2 게이트 순서 (Commit 내부 — 청사진 §04와 동일)

쿨다운 — IClock.Now < _cooldownEnd[a] 이면 아직 쿨 → 중단 (절대시각, tick 불필요)
코스트 — resource.CanPay(a) 부족하면 중단(미소모). 통과 시 resource.Pay(a)
태그 — HasAll(Required) && HasNone(Blocked) (기절 중 발동 불가 등)
쿨 시작 — _cooldownEnd[a] = Now + Cooldown·CDR → (Fire에서 캐스트타임 + 이펙트)
1~3 실패 시 — 상태변화 없이 조용히 중단, 쿨·코스트 미소모
순서 결정 필요 코스트 소비를 태그 게이트 앞에 두면 태그 실패 시 궁게이지가 샌다. 안전하게 "검사 전부 통과 → 마지막에 Pay+쿨시작" 으로 짜길 권장(§8-c).

03코스트 이음새 — 유일하게 새로 잇는 배선

에너지는 Stat에 남고, 러너는 소비 순서만 소유. AbilityData.Cost는 지금 죽은 필드 — 여기가 실제 배선점.

3.1 비용 종류 (Q의 "궁게이지" 의미 보존)

Q의 코스트는 정수가 아니라 "에너지 만충 요구 + 전량 소비". E·평타는 없음. 이를 담으려면 AbilityData에 종류 필드를 둔다.

public enum EAbilityCostType { None, Energy, UltimateGauge }

// Cost(int) 는 CostType==Energy 일 때만 의미 (기존 필드 재사용)

3.2 자원 제공자 인터페이스

AbilityContext.CasterStat은 BaseStat. 코스트는 캐릭터 전용이라 인터페이스로 얇게 얹고 러너는 널체크한다(몬스터 미구현 → 코스트 없음).

public interface IAbilityResource
{
    bool CanPay(AbilityData a);
    void Pay(AbilityData a);   // 호출 후 OnEnergyChanged / 궁 준비 재평가는 구현체 책임
}
// CharacterStat : BaseStat, IAbilityResource  → 위 표대로 구현
// 러너 Commit 내부:
var res = ctx.CasterStat as IAbilityResource;
if (res != null && !res.CanPay(a)) return false;
// ... 전 게이트 통과 후 ...  res?.Pay(a);

04슬롯별 admission / fire 매핑 (Phase 1)

규약 — 슬롯의 쿨·코스트 대표 어빌리티는 _slotMap[slot][0]. 비트는 각자 list[beat] 이펙트만 발사(무게이트).

슬롯admission (입력)fire
평타Commit(atk0) 로 Attack 입장 게이트각 비트 → Fire(list[beat])
QCommit(q0) 로 컷신 입장 (궁게이지 여기서 소비)각 비트 → Fire(list[beat])
ETryCast(ex0) 입력 시점 즉발(Commit+Fire) — Phase 1 경로 유지— (Phase 2에서 비트로)

atk0=_slotMap[Attack][0], q0=_slotMap[Skill][0], ex0=_slotMap[Ex][0].

BaseCharacter 진입점 재작성 (명세)

// 평타
public void Attack(bool isPressing) {
    if (!isPressing) return;
    if (!_stateMachine.CanAttack || IsUsingSkill || Stat.HealthComp.IsDead) return;
    if (!TryCommitSlot(CharacterAbilitySlot.Attack)) return;   // ← _combat.CanAttack/TryAttack 대체
    _stateMachine.ChangeState(PlayerState.Attack);
}
// Q
public void UseSkillQ() {
    if (!_stateMachine.CanUseSkill || IsUsingSkill || Stat.HealthComp.IsDead) return;
    if (!TryCommitSlot(CharacterAbilitySlot.Skill)) return;    // ← _combat.TryUseSkillQ 대체 (궁+쿨)
    _stateMachine.ChangeState(PlayerState.QSkillCutScene);
}
// E (Phase 1: 즉발 유지)
public void UseSkillE() {
    if (!_stateMachine.CanUseSkill || IsUsingSkill || Stat.HealthComp.IsDead) return;
    if (!CanCastSlot(CharacterAbilitySlot.Ex)) return;              // 입장 판정만(소비 X)
    _stateMachine.ChangeState(PlayerState.E_Skill);
    FireSlotImmediate(CharacterAbilitySlot.Ex);                   // TryCast(ex0)=Commit+Fire
}
// 비트: 이펙트만 (무게이트)
public void UseAbility(CharacterAbilitySlot slot, int beat = 0) {
    if (_slotMap.TryGetValue(slot, out var list) && beat >= 0 && beat < list.Count)
        FireEffectsOnly(list[beat]);   // ← 기존 TryCast(list[beat]) 를 Fire 로 교체
}
  • TryCommitSlot(slot) = _slotMap[slot]?[0]로 ctx 만들어 _abilityRunner.Commit(a,ctx).
  • FireEffectsOnly(a) = ctx+token 만들어 _abilityRunner.Fire(a,ctx,token).Forget().
  • E도 TryCommitSlot+FireEffectsOnly로 통일해도 됨(권장, 경로 일관).
다중 비트 자기차단 주의 (덤으로 잡히는 버그) 지금 비트마다 TryCast(list[beat])라 같은 어빌리티를 2비트에서 쓰면 두 번째가 자기 쿨에 막혀 조용히 씹힌다. 비트를 무게이트 Fire 로 바꾸면 이 잠복 버그도 사라진다(쿨은 admission 한 번만).

05UI 읽기 — Stat 쿨 필드 → 러너 조회

HUD/슬롯UI가 읽던 stat.CurrentQSkillCoolTime 가 사라진다. BaseCharacter 얇은 파사드로 러너를 조회.

// BaseCharacter (읽기 파사드)
public float SlotCooldownRemaining(CharacterAbilitySlot s);  // 러너 CooldownRemaining(slot0)
public float SlotCooldownDuration(CharacterAbilitySlot s);   // 러너 CooldownDuration(slot0)
public bool  IsUltimateReady =>                              // 궁 준비 = 에너지 만충 && Q 쿨 0
    Stat.CurrentEnergy >= Stat.MaxEnergy.Value
    && SlotCooldownRemaining(CharacterAbilitySlot.Skill) <= 0f;

바꿀 곳

  • ActiveCharacterHUD.UpdateCooldowns(stat) → UpdateCooldowns(BaseCharacter c)로 변경, c.SlotCooldownRemaining/Duration(Skill|Ex)로 채움. 호출부 GameSceneCanvas.Update는 이미 매 프레임 폴링 중.
  • SubscribeEvent/PartySlotUI의 isReady 계산 → c.IsUltimateReady.
궁 준비 이벤트(OnUltimateStateChanged) 처리 — 결정 포인트 쿨이 절대시각(무tick)이 되며 "쿨 방금 0 됨" 전이를 쳐줄 주체가 없어진다. 활성 캐릭터는 GameSceneCanvas.Update 폴링에서 c.IsUltimateReady 계산해 푸시. 벤치 멤버는 §6의 경량 ready 재평가 패스가 전이 시 이벤트를 계속 쳐 주면 슬롯UI 변경 최소화.
(a) 이벤트 유지 + 소스만 러너로 (권장) vs (b) 이벤트 제거 + 전부 폴링.

06PartyManager.TickCooldowns 처리

  • 쿨 진행 목적은 삭제 — 쿨이 절대시각이라 벤치 멤버도 Now가 흐르면 자동 경과. Stat.TickCooldowns/Current*CoolTime/QSkillCoolTime/ESkillCoolTime(Stat) 전부 제거.
  • 대체(선택, 5-(a) 채택 시) — 그 자리에 궁 준비 재평가 패스만 남긴다. dt 계산 없이 각 멤버 IsUltimateReady를 재계산해 이전 값과 다르면 OnUltimateStateChanged를 친다(멤버당 bool 비교뿐, 기존보다 가벼움). 이름 RefreshUltimateReady() 등.
  • Managers.Update의 TickCooldowns(dt) 호출부도 교체/제거.
