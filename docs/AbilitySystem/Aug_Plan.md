## 왜 (지금 아쉬운 3가지 → 이 계획이 메움)

| 아쉬움 | 이 계획이 메우는 법 |
|---|---|
| 공유 파이프라인으로 **뭐가 벌어지는지 안 보임** | 버프·방깎·(표식)이 한 데미지에 합쳐지는 **머니샷 데모** |
| 태그·상태(Status)가 **아무 일도 안 함** | 방깎/버프가 실제 스탯에 걸리고 만료됨 + (선택)Marked 게이팅 |
| **성능 숫자 0** | 캐스트 GC/alloc Before/After 측정 |

## 머니샷 (핵심 데모 장면)

```
브레이커 → 적에게   [방어력 −]  (+선택 Marked)     ← 몹이 Effect를 받음
버퍼    → 아군에게 [공격력 +]                      ← 플레이어가 Effect를 받음
딜러    → 때림
─────────────────────────────────────────────
최종 데미지 = 공격력(버프 +30%)  vs  방어력(방깎 −40%)  (+Marked 보너스)
             └─ 한 공식이 여러 modifier를 읽고, 각 modifier는 소스별 독립 만료 ─┘
```
**포폴 포인트 = 이 공식이 화면/로그에 보이는 것.** VFX 반짝임이 아니라 "여러 modifier가 정확히 합산·독립관리된다"가 값.

## 4주 계획 (주차별 산출물 + 검증)

### Week 1 — 활성화(배선): 효과가 실제로 걸리게
- 브레이커: 적에게 방깎(−Def) `ApplyStatModifier(scope=Target)` — bullet `_onHitEffects` 또는 E로 연결.
- 버퍼: 파티에 +Atk `ApplyStatModifier(scope=Party)` E 연결. 각 캐릭 프리팹 `RoleData`/E 자산 배선 점검.
- **검증**: 로그로 적 Defense 값이 내려갔다 duration 후 복구 / 파티 Attack 올랐다 복구. (StatusRunner 만료 동작)
- **산출물**: 브레이커·버퍼·딜러 한 파티로 전투 진입, 효과가 스탯에 반영됨.

### Week 2 — 가시화(핵심, 유일한 신규 작업): 데미지 공식 표시
- 데미지 계산 시점에 항을 노출: `base Atk · 버프 modifier · target Def · 방깎 modifier · (Marked 보너스) → 최종`.
- 디버그 오버레이(또는 온스크린 로그)로 히트마다 공식 표시.
- **소스 추적 검증**: 버프만 만료돼도 방깎은 유지(각 modifier가 source로 독립 제거).
- **검증**: 한 히트 최종 데미지 = 공식대로 · 항이 눈에 보임 · 버프/방깎 독립 만료 확인.
- **산출물**: "공격력(+30%) vs 방어력(−40%) → 최종 XXX" 가 보이는 화면.

### Week 3 — 데모화: Before/After 슬라이스
- 짧은 전투 슬라이스: ① 딜러 단독 타격 ② 표식→버프 얹고 타격 → 데미지 점프.
- (선택 깊이) Marked 태그가 딜러 추가데미지를 **게이팅**(태그 실사용 증명).
- GIF/영상 2개 캡처(Before/After).
- **검증**: 콤보 시 데미지가 눈에 띄게 점프, GIF로 대비됨.
- **산출물**: Before/After GIF 2개.

### Week 4 — 측정 + 정리
- 캐스트 경로 GC/alloc Before/After(Profiler) — `CreateRuntime()=>this` 무할당 증명.
- 포폴 1페이지: 머니샷 GIF + 정량지표(발동 3→1 · 새 스킬 코드 0 · 합산 파이프라인) + 소스추적 합산 서술.
- **검증**: 캐스트 시 힙 할당 0(또는 Before 대비 급감) 스크린샷 · 1p 초안 완성.
- **산출물**: 측정 스크린샷 + 포트폴리오 1페이지.

## 측정 계획 (약점 보강)
- **무엇**: 어빌리티 1회 캐스트의 힙 할당(B). **도구**: Unity Profiler(GC Alloc) 또는 `Recorder`.
- **가설**: `EffectData.CreateRuntime()=>this`(stateless) + ctx 재사용이라 캐스트당 할당 ≈ 0.
- **주의**: 에디터 측정은 과대계상 가능 → 상대 비교(Before/After)로 제시, 절대값 단정 금지.

## 리스크 / 결정 포인트
- **(a) 데미지가 이미 target Defense를 읽는가** — 읽으면(피해=max(dmg−def,1)) 방깎은 자동 반영, 가시화만 추가. 안 읽으면 Week1에 계산식 점검 먼저.
- **(b) Marked 게이팅 포함 여부** — 코어(버프+방깎)는 태그 없이 성립. 시간 남으면 Week3에 +1로.
- **(c) 디버그 표시 방식** — 온스크린 텍스트 vs 기존 데미지 토스트 확장. 가장 빨리 되는 것으로.
