# AbilitySystem 포트폴리오 가치 강화 — 할 일

> **목적** — 이관을 끝낸 AbilitySystem(→ [README](README.md)·[BossMigration](BossMigration.md)·[CharacterMigration](CharacterMigration.md))을 **게임 클라이언트 포트폴리오 소재로서 한 단계 격상**시키기 위한 작업 백로그. "더 많이 만들기(넓이)"가 아니라 **약점을 정면으로 때우기(깊이)** 가 목표.

## 0. 현 상태의 객관적 평가 (왜 이 작업이 필요한가)

**결론**: 직무 정합성은 높지만(전투/스킬 시스템 = 게임플레이 클라 핵심), 그 자체로는 **"잘 만든 표준 구현"** 수준. 신입~주니어 상위권 소재이나 단독 킬러는 아님.

| 강점 (유지) | 약점 (이 문서가 때움) |
|---|---|
| 직무 정합성 높음 (전투 시스템) | ① 패턴 자체가 흔함 (SO+Effect 조합 = 정석) |
| 설계 성숙도·트레이드오프 판단 | ② 지표가 '구조 프록시'뿐, **성능 실측 없음** (Sector의 프로파일러 수치 대비 약함) |
| Unity 도메인 이해 | ③ 자기가 만든 문제를 자기가 치움 (학습형 리팩터) |
| | ④ 프레임예산·할당·상태관리 등 **'하드한' 클라 주제 미접촉** |

→ **핵심 전략**: 약점 ②(성능 근거)와 ④(하드 주제)를 채우면 "구조 소재"가 "성능·시스템 소재"로 격상된다.

> ⚠️ **하지 말 것**: Effect 종류 추가, 캐릭터 추가 이관, "확장 비용 0" 과장. 전부 넓이라 가치를 거의 안 올리고, 과장은 면접 되치기만 키움.

## 1순위 — 캐스트 경로 GC/Allocation 실측 ★필수★

**때우는 약점: ②(성능 근거 없음).  ROI 최고 — 이미 설계에 들어있어 '측정'만 하면 됨.**

### 배경
`EffectData.CreateRuntime() => this` — 무상태 Effect는 SO 인스턴스를 공유하므로 **캐스트당 힙 할당 0**. 이건 말이 아니라 **측정 가능한 주장**이다. (상태 있는 Effect만 `new`)

### 할 일
- [ ] Before 버전 준비: 매 캐스트마다 Effect를 `new`로 찍는 순진한 구현(비교군).
- [ ] After = 현재(`=> this` 공유) 구현.
- [ ] Unity Profiler(또는 `GC.GetTotalAllocatedBytes`)로 **연사/버스트 N회 캐스트 시 GC.Alloc 바이트** 측정.
- [ ] Before/After 비교 캡처 (예: "라이플 연사 8발 × M회 → X KB → **0 B**").

### 산출물 / 완료 기준
- 프로파일러 스크린샷 1장 + Before/After 수치 표 1개.
- 포트폴리오 문제해결(2)-2 표에 **성능 행 1줄** 추가 → 구조 지표 옆에 실측 성능 지표 병기.

### 노력: **작음** (1~2일). 시스템 변경 없이 계측만.

## 2순위 — 어빌리티 에디터 툴 (검증 + 시각화)

**때우는 약점: ①(흔함) → "안전·사용가능하게 만든다"는 시니어 신호로 반격. 기존 Excel→SO 툴링 테마와 연결.**

### 배경
실제로 겪은 조합 함정이 있음(문서화됨): **`RepeatEffect` 자식 `SpawnProjectiles._count`가 1이 아니면 `5×5=25`발**. 조합형 시스템은 이런 무언의 함정이 생기는데, 이를 **툴이 잡아주는지**가 성숙도.

### 할 일
- [ ] `AbilityData` / Effect용 **커스텀 인스펙터 + 밸리데이터**:
  - RepeatEffect 자식의 `SpawnProjectiles._count != 1` → 경고
  - 빈 `_effects` / null 참조 → 경고
  - `SpawnProjectiles._bulletPrefab`에 `IProjectile` 없음 → 경고
  - `RepeatEffect` 안에 또 `RepeatEffect`(의도치 않은 중첩) → 정보
- [ ] (선택) Effect 체인을 **트리로 시각화**하는 에디터 창.

### 산출물 / 완료 기준
- 밸리데이터 스크린샷(경고 뜨는 화면) 1~2장.
- "조합의 안전성을 툴로 보장" 한 문단 → 문제해결(2) 보조 슬라이드 또는 부록.

### 노력: **중간** (2~4일). 에디터 스크립트(`OnValidate` / `CustomEditor`).

## 3순위 — StatusSystem (DoT / 버프 / 디버프) — 깊이의 정점

**때우는 약점: ①·④(흔함 + 하드 주제). 노력 크지만 천장이 가장 높음.**

### 배경
문서의 미완 TODO. 어빌리티 시스템이 **진짜 어려워지는 지점**. 지금은 "발동·발사"까지고 **상태 지속 관리가 없음** → 많은 포트폴리오 어빌리티 시스템이 똑같이 빠뜨리는 부분.

### 할 일 (설계 포인트 = 면접 소재)
- [ ] `StatusSystem`(대상 소유) + `ApplyStatus` Effect(부착만) 분리.
- [ ] **tick 소유권**: 대상이 독립적으로 tick/갱신/제거 (Effect는 무상태 유지).
- [ ] **스택 정책**: 중첩(stack) / 갱신(refresh) / 독립(separate) 을 데이터로 선택.
- [ ] 지속시간 리프레시, 만료 정리, **대상 사망 시 안전 해제**(null·풀 반환 가드).
- [ ] DoT 데미지도 `BuildOutgoingDamage` 크리 경로 재사용.

### 산출물 / 완료 기준
- 스택 정책 3종 데모 + "상태의 소유자" 설계 서사(캐스터 vs 대상 vs asset).
- 문제해결(2)에 "상태 지속 관리" 축 추가 → "표준 구현"에서 이탈.

### 노력: **큼** (1~2주). 대표 심화로 밀 때만.

## 선택 — 풀링 연계 프레임 예산 스트레스

**때우는 약점: ②·④. 기존 #2 플래그십(비동기 리소스·풀링)과 한 서사로 묶기.**

### 할 일
- [ ] N마리 동시 캐스트 스트레스 씬 → 투사체/VFX **풀링이 프레임 스파이크를 막는지** 프로파일러 캡처.
- [ ] 풀링 on/off Before/After 프레임타임.

### 주의
- 최종 설계가 **단일 섹터**라 대량 동시 캐스트는 실전에 없음 → **합성 스트레스임을 정직히 명시**(과장보다 이게 시니어 시그널). 그래서 '선택'.

### 노력: 중간.

## 권고 조합 & 순서

1. **최소 (필수)**: 1순위(GC 실측). 최대 약점(성능 근거 부재) 제거. 며칠.
2. **현실적 최적**: **1순위 + 2순위**. 서로 다른 축(성능 근거 / 툴링 성숙도)을 채워 방어가 두꺼워짐. 둘 다 단기.
3. **대표작으로 밀 경우**: + 3순위(StatusSystem)까지. "제대로 된 전투 시스템"으로 격상.

## 포트폴리오 반영 지점
- 문제해결(2)-2 Before/After 표에 **성능 행**(1순위) 추가.
- 문제해결(2) 부록/보조 슬라이드에 **밸리데이터 스크린샷**(2순위).
- 3순위 완료 시 **"상태 지속 관리" 축**을 문제해결(2)-1 설계 원칙에 편입.
