Operation Kivotos · AbilitySystem · 개념 정리 (서사 재료)

무엇을 누가 소유하나

플레이어·보스·몬스터가 각자 갖고 있던 공격 코드를 AbilityRunner 단일 창구로 모아 쿨타임·비용 판단을 한 곳에서 하게 했다. 실제 효과는 자주 쓰는 패턴을 Effect로 정의해두고 조합해서 만든다. 효과가 나가는 순간은 애니메이션 이벤트가 담당해 타격감을 살렸다.

큰 그림

전에는 공격 코드가 3벌·쿨타임이 여러 곳. 지금은 한 창구로.

새 스킬 = 코드가 아니라 데이터(Effect) 조합.

핵심 — "발동 타이밍"은 두 가지 뜻

여기가 설명할 때 헷갈리는 지점. 러너가 다 갖는 게 아니라 둘로 갈린다.

무엇뜻소유자
발동 자격 판단"지금 써도 되나?" — 쿨 끝났나 · 비용 되나 · 태그 되나AbilityRunner
실제 발사 순간"애니메이션 어느 프레임에 총알/효과가 나가나"애니메이션 이벤트
자랑 포인트 "판단은 시스템(러너)이, 타이밍은 애니메이션이." 이 역할 나눔 덕에 ① 쿨·비용 규칙이 한 곳에서 관리되고 ② 발사가 애니 프레임에 정확히 붙어 타격감이 산다.

소유권 지도 — 누가 무엇을

한 줄 규칙: 판단·규칙 = 시스템 / 무엇을 = 데이터 / 언제·연출 = 애니메이션.

그대로 써먹을 문장

  • (한 줄) "플레이어·보스·몬스터가 각자 갖던 공격 코드를 단일 창구로 모으고, 효과는 재사용 패턴을 조합해 데이터로 만들었다."
  • (관심사 분리) "발동해도 되는지(쿨·비용)는 시스템이, 실제 발사 순간은 애니메이션이 갖게 나눴다."
  • (효과 조합) "자주 쓰는 동작을 Effect로 정의해두고, 새 스킬은 코드 없이 이들을 조합해 만든다."
  • (결과) "발동 경로 3→1, 새 스킬 = 데이터 조합(코드 0), 쿨타임 관리 코드 뭉치 삭제."
