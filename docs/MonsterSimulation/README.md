## 한 줄 요약

기존 Sector(트리거 기반 구역 활성화)는 **정상 상태 CPU만** 잡았고, **경계에서 전투 중인 몬스터가 사라지는 버그**와 **화면(25m)보다 훨씬 큰 판정 단위(100m)** 라는 두 문제를 남겼다.
이를 **①증상 봉합(리쉬) → ②구조 정비(제어점) → ③정책 적용(시간·거리·예산)** 순으로 푼다.

## 서사 (포트폴리오 슬라이드 골격)

```
① 전체 스포너 활성화            맵 전체 AI/렌더 병목
        ↓
② Sector 기반 구역 활성화       [현재] 정상 상태는 잡힘
        ↓                      ⚠ 경계에서 전투 중 몬스터가 눈앞에서 소실
②' 전투 유예 + 리쉬 복귀        증상은 사라짐
        ↓                      ⚠ 그러나 여전히 화면 밖 100m를 통째로 켬 (= 최적화 아님)
③ 몬스터 시뮬레이션 재설계       근본 원인 = 판정 입자가 화면보다 컸던 것
   (제어점 + 시간 분산 + 거리 + 예산)
```

**핵심 메시지**: "증상을 막는 것"과 "원인을 없애는 것"은 다르다.
처음부터 정답을 알던 것보다, **임시방편을 대보고 그게 왜 부족한지 측정으로 알아낸 서사**가 더 강하다.

## 확정된 결정

- **인접 섹터 그래프는 쓰지 않는다** — 수동 배선이 썩고, 섹터 단위가 화면보다 훨씬 크다
- **존재(스폰/디스폰)는 거리로, 품질(틱·컴포넌트)은 점수로** — 두 축을 절대 섞지 않는다
- **점수·예산(B층)은 조건부** — A층 실측 분포(35m 내 몬스터 수 최댓값)를 보고 착수 판단
- **보스는 이관 대상에서 제외** — Timeline·Signal 결합으로 회귀 위험이 큼
- **Sector 볼륨은 남긴다** — 역할만 "성능 판정" → "게임플레이 구역(이름·BGM·필드보스)"으로
