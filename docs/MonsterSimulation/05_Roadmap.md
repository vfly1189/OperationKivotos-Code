# 05. 로드맵 · 측정 계획 · 포트폴리오 반영

## 0. 원칙

1. **재고 나서 고친다.** 먼저 적용해버리면 기준선이 흔들려 각 단계의 기여를 분리할 수 없다.
2. **각 단계에서 멈춰도 완결된 이야기가 되게 한다.** (일정 리스크 대응)
3. 아래로 갈수록 **이득이 크고 위험도 크다.**

---

## 1. 단계

```
S0  Before 박제 + 계측 하네스      ← 가장 먼저. 되돌릴 수 없는 기록 확보
 ↓
②'  전투 유예 + 리쉬 복귀          ← 경계 버그 해결 (작음)
 ↓
S1  설정 최적화 (축2·설정)         ← 체크박스 수준. 단, 반드시 개별 측정
 ↓
①   시뮬레이션 매니저 (제어점)      ← 수치 없음. 토대
 ↓
②③ 시간 분산 + 틱 그룹            ← 여기서 첫 수치가 나온다
 ↓
A   거리 기반 존재 관리            ← 가장 큰 절감
 ↓
B   중요도 점수 + 예산             ← 조건부. A 실측 결과로 판단
```

### S0 — Before 박제 + 계측 하네스 · 2~3일
- ⚠ **최우선: "경계에서 전투 중 몬스터가 사라지는" 영상 촬영.** ②'를 고치면 다시 못 찍는다
- `SimMetrics` (개발 빌드/에디터 가드):
  - 프레임타임 링버퍼 → p50 / p99 / **1% low**, `>33ms` 히칭 프레임 수
  - **활성 몬스터 수**, **35m 이내 몬스터 수** (B층 착수 판단의 근거가 되는 핵심 지표)
  - AI 시뮬 구간 `ProfilerMarker`
- **자동 워크 하네스** — 플레이어를 웨이포인트로 스크립트 이동시키는 재현 시나리오
  - `WALK`: 섹터 1→5 종주
  - `EDGE`: 경계 왕복 10회
  - `PULL`: 몬스터를 한 곳으로 유인 (B층 무대)
  - 손으로 걷는 측정은 신뢰도가 없다. ResourceSystem의 변수 통제와 같은 급으로 맞춘다
- 기존 자산 재사용: `MetricsHotkeys`(F5~F9), `ResourceMetrics.LogRuntimeMemory`, `LogAliveReport`
- **산출물**: `Baseline.md` — v1 수치표 + 로그 원본 + 영상. 여기서 커밋해 Before를 박제

### ②' — 전투 유예 + 리쉬 · 1주 이내
- 몬스터 → 스포너 "사용 중" 등록/해제 (**집합 기반**)
- 리쉬 복귀 상태를 BT에 추가 (복귀 중 피격·HP 처리 정책 결정 필요)
- **유예 최대 시간** 강제
- 유지 단위는 **스포너**
- **측정**: 평균/최대 활성 몬스터 수 변화 (증가할 것 — 그게 ③의 착수 근거)

### S1 — 설정 최적화 · 1~2일
- Animator Culling Mode → `Based on Renderers`, SkinnedMeshRenderer `Update When Offscreen` 해제
- NavMeshAgent 회피 품질 하향
- 레이어 충돌 매트릭스 정리
- `Physics.OverlapSphere` → `NonAlloc` + 재사용 버퍼 ([AreaStrike.cs:54](../../Assets/Scripts/Data/Ability/Effects/Damage/AreaStrike.cs:54))
- `Vector3.Distance` → `sqrMagnitude` 비교 ([NormalMonsterController.cs:179](../../Assets/Scripts/Controllers/Monster/NormalMonsterController.cs:179))
- ⚠ **반드시 이 단계만 따로 측정.** 안 그러면 구조 개선의 효과와 뒤섞인다

### ① — 시뮬레이션 매니저 · 1주
- 몬스터 Update 이관 (**보스 제외**)
- 등록/해제 대칭 + 주기적 청소, 제거 대기 큐
- **경과 시간 주입** (deltaTime 오염 차단)
- `ProfilerMarker` 삽입
- 데이터는 배열 기반으로
- **측정**: 수치 변화 거의 없을 것으로 예상 → 단독 성과로 제시하지 않는다

### ②③ — 시간 분산 + 틱 그룹 · 3~5일
- 60Hz / 10Hz / 2Hz 버킷 + 위상 오프셋
- "생각은 가끔, 움직임은 매 프레임" 규칙 적용
- 승격 즉시 / 강등 유예
- **측정**: 프레임타임 p99·1% low, 히칭 수

### A — 거리 기반 존재 관리 · 1~2주
- `CullingGroup`에 **스포너** 등록, 밴드 `{25, 35, 50}`, 기준점 = 플레이어
- `isVisible == false` 우선 스폰/디스폰
- `NeverDespawn` 플래그
- 트리거 기반 섹터 활성화 제거 → Sector 볼륨은 게임플레이 전용으로 역할 변경
- **측정**: 활성 몬스터 수, 프레임타임, **35m 내 몬스터 수 분포** ← B층 판단 근거

### B — 중요도 점수 + 예산 · 조건부 1~2주
- A의 실측 분포를 보고 착수 여부 결정
- 착수 시: 점수 계산(A층 값 재사용) + 버킷 커트라인 + 티어 정원 + dwell time
- 전투 중 하드 잠금
- **측정**: `PULL` 시나리오에서 A만 vs A+B

## 2. 측정 계획 ★가장 중요★

### 조건을 분리해서 잰다
각 단계의 기여를 나중에 분리하는 건 불가능하다. **처음부터 조건별로 커밋을 남긴다.**

| 조건 | 무엇을 증명하나 |
|---|---|
| ② Sector (현재) | baseline |
| ②' + 전투 유예 | 버그 해결. **활성 수는 늘어남**(정직하게 기록) |
| ②' + S1 설정 최적화 | **설정만의 기여** |
| + ①②③ 구조 | **시간 분산의 기여** |
| + A 거리 | **존재 관리의 기여** (가장 클 것) |
| + B 예산 | **B의 순수 기여** — 평상시 vs `PULL` 상황 따로 |

### 오버헤드 vs 절감 표
"점수 계산이 비싸지 않냐"는 면접에서 **반드시 나온다.** 추측이 아니라 표로 답한다.

| | 값 |
|---|---|
| 채점 + 버킷 (활성 N마리, 5Hz) | ? ms |
| 그 결과로 잠재운 Animator/NavMeshAgent | ? ms |
| **비율** | ? |

### 주의
- 에디터 프로파일러는 과대계상 → **개발 빌드 실측** (파이프라인 이미 구축됨)
- 상대 비교로 제시

## 3. 포트폴리오 반영

### 슬라이드 골격 (4단 서사)
| 장 | 내용 |
|---|---|
| 문제상황(1) | 기획 변경(포탈→단일 필드) → 전체 스폰 병목. **공간 분할로 정상 상태를 잡음(▼57%/▼67%)은 여기 = 출발점으로 이동** |
| 문제해결(1)-1 | **경계에서 전투 중 몬스터가 사라진다** (Before 영상) → 전투 유예·리쉬로 봉합. **그러나 화면 밖 100m를 여전히 켜고 있다** |
| 문제해결(1)-2 | 근본 원인 = 판정 입자가 화면보다 컸음. 제어점 확보 → 시간 분산 → 거리 기반 존재 관리 |
| 문제해결(1)-3 | v1 vs v2 비교표 + (B 착수 시) 몹 몰이 프레임 상한 |

### 머니샷
- **경계 소실 Before/After** (버그 → 해결)
- **몹 몰이 시 프레임 유지** (B 착수 시. 이 장르에서 몹 몰이는 정상 플레이라 "합성"이라 변명할 필요 없음)
- **디버그 뷰 스크린샷** (머리 위 티어·점수)

### 하지 말 것
- ①(매니저 이관)을 단독 성과로 제시
- 규모를 부풀려 "필요했다"고 주장 — "한계를 확인하려고 만들고 경계를 측정했다"가 정직하고 방어도 강하다
- 클래스 수·LOC 같은 vanity metric
