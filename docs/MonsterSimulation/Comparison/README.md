# 몬스터 관리 방식 비교 — 5가지 방법

> 작성: 2026-08-19 · 대상: 포트폴리오 Unity 파트 **문제해결(1)** 재설계
> 상위 폴더 [MonsterSimulation/](../)의 **비교 실험 트랙**. 01~05가 "무엇을 만들까"라면 여기는
> **"여러 방법을 만들어서 재고, 그걸로 무엇을 주장할까"** 를 다룬다.
> **이 README만 읽어도 맥락 없이 재개할 수 있도록** 결론을 요약해 둔다.

## 한 줄 요약

같은 문제("큰 맵에서 누구를 켜둘 것인가")에 대한 **5가지 방법을 전부 구현해서 같은 기준으로 재고**,
그 결과로 "이 게임의 조건에서는 이 조합"이라는 결론을 낸다.
파는 것은 기법이 아니라 **선택의 근거**다.

> **관통 질문 (2026-08-22 확정)**
> **플레이어가 눈치채지 못한다는 조건 아래서, 어디까지 줄일 수 있나**
>
> "3000마리를 어떻게 싸게 돌릴까"가 아니다. 성능은 *얼마나 벌 수 있나*(상한)를,
> 체감은 *얼마나 써도 되나*(제약)를 답하고 **결론은 둘의 교집합**에서 나온다.

## 서사 (포트폴리오 슬라이드 골격)

```
출발점    방법2 (단일 Sector)  ← 내가 만들어 굴리던 것. 여기서 문제 발견
   ↓
시도 1    방법3  섹터 유지하고 예외 처리   → 버그는 고침, 성능은 그대로
시도 2    방법4  틀을 바꿔 거리 기반       → 규모 해결, 밀집 취약
시도 3    방법5  끄지 말고 느리게          → 밀집 해결, 규모 취약
   ↓
결론      게임 조건에 대입 → 4와 5를 층으로 나눠 겹침
   ↓
마무리    껐는데 메모리는 안 줄어 있었다 → 리소스 수명(Addressable) 파트로 연결

참조선    방법1 (전체 활성화)  ← 서사에는 안 나오고, 측정 표의 상한선으로만 등장
```

> **⚠ 2026-08-22** — 위 골격에서 방법4가 본론, 방법5가 확장이다. 그러나
> [03_Predictions 6.1](03_Predictions.md)에 **"이 장르에서는 방법5가 주역일 것"** 이라는 예측을 박제했다.
> 밀도가 1차 병목으로 확인되면 **4는 전제, 5는 본론**으로 무게가 이동한다.
> **측정 전에 확정하지 않는다.**

**핵심 메시지**: "증상을 막는 것"과 "원인을 없애는 것"은 다르다.
그리고 **방법3은 일부러 실패하는 단계**다 — 섹터라는 틀 안에서는 정확성과 성능을 동시에 못 잡는다는
것을 숫자로 보여주는 게 그 방법의 역할이고, 그래야 방법4가 "하나 더 해봤다"가 아니라 필연이 된다.

## 확정된 결정

- **서사의 출발점은 방법2(단일 Sector)** — 방법1(전체 활성화)은 내가 설계한 게 아니라 "아직 아무것도
  안 한 상태"라, Before로 쓰면 인위적이다 ([01_Problem 3.2](../01_Problem.md) 참고). 표에는 상한선으로 남긴다
- **5가지 전부 구현해서 잰다** — "비교했다"고 쓴 것 중 실제로 안 만든 게 있으면 질문 한 번에 무너진다
- **인접 섹터 켜기는 구현하지 않는다** — 화면 25m인데 섹터 100m라 낭비가 2~3배로 늘 뿐.
  비교표 행이 아니라 "검토 후 기각" 각주로 처리
- **결론은 하나를 고르는 게 아니라 두 층을 겹치는 것** — 방법4로 존재를, 방법5로 품질을 정한다.
  둘은 축이 직교해서 경쟁 관계가 아니다
- **끝은 성능이 아니라 메모리로 닫는다** — G4(껐는데 메모리가 안 줄었다) → Addressable 파트로 연결
- **평균 FPS는 지표로 쓰지 않는다** — p99 / 1% low / 히칭 프레임 수만

### 2026-08-22 추가 결정

- **축을 뒤집는다 — 밀도가 1차, 총량이 2차** — 이 장르(쿼터뷰·화면 25m 고정·무리 배치)에서는
  화면 내 개체 수에 구조적 상한이 있어 총량이 병목이 아니다. 몹 몰이가 정상 플레이라 밀도가 병목이다.
  총량 축은 **곡선의 기울기만 읽는 확장성 증거**로 남긴다 → [02_Measurement 3절](02_Measurement.md)
- **총량 3000은 목표가 아니라 극한값** — "그럴 일 없지 않나요?"에 대한 답변을
  05_PortfolioNarrative 5.9(비공개)에 박아둔다. 규모를 부풀려 정당화하지 않는다
- **체감을 1급 지표로 승격** — 팝인 횟수 · 깜빡임 · 반응 지연 · 이동 저크.
  이게 없으면 "왜 45m죠?"에 답할 수단이 없고 결론이 "제일 싼 걸 골랐다"로 축소된다
  → [02_Measurement 4.3](02_Measurement.md)
- **"200에서 차이 없음"을 헤드라인으로** — 숨기지 않는다. 지원처가 정해지지 않은 상태에서
  **양쪽 청중에 동시에 먹히는 유일한 결과**다 → 05_PortfolioNarrative 5.10(비공개)
- **측정 전 통제 변수 확보를 앞에 둔다** — 현재 풀 프리워밍(30)이 실제 필요치(119)에 못 미쳐
  히칭 지표가 **방법의 차이가 아니라 풀 부족**을 재고 있다 → [07_Prerequisites](07_Prerequisites.md)
- **스포너 배치 리팩터(앵커+패턴)는 실험 후로 미룬다** — 스트레스 씬이 배치를 우회하므로
  실험 경로에 불필요하고, 실험 중 배치가 바뀌면 이전 측정치가 전부 무효가 된다
- **덱 안에서 이 트랙은 병렬 3번이 아니라 척추** — 리소스·어빌리티 둘 다에 닿는 유일한 노드
