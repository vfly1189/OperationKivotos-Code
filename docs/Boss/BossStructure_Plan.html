보스 구조 — 컨테이너 + 패턴 조각

레퍼런스: 로스트아크 레이드. 평소에는 짤패턴을 무작위로, 체력이 정해진 줄에 닿으면 정해진 패턴(기믹)을 수행한다. 보스마다 스크립트를 만들지 않고, 공통 컨테이너에 조각을 끼워 맞춘다.

1. 전투 흐름

평상 루프와 고정 패턴
체력 줄에 따라 나오는 패턴 (예시 구성)

2. 결정 사항

#질문결정
D1한 번에 여러 줄을 넘거나, 기믹 중 다음 줄에 닿으면넘은 기믹을 전부 순서대로 실행. 사망만 예외 → 기믹 대기열
D2짤패턴 도중 줄을 넘으면모든 패턴은 원자적. 하던 패턴이 끝난 뒤 기믹
D3기믹 중 체력잠그지 않음. 계속 피격 가능
D4기믹 이후 짤패턴 변화NextFillers — 비우면 유지, 채우면 교체
D5사망 시 정리 범위타임라인 · 장판 · 투사체 정리, 소환물은 사망 때 일괄 정리
D6조각의 크기와 재료패턴 단위 조각(컴포넌트) + 기믹 조건 조각(SO)
D7결정 구조BT를 기본으로
D8사거리 밖사거리까지 이동 후 진행. 지금은 고정형이라 추적 생략

3. 구조 — 조각은 "무엇을", 표는 "언제"

보스 프리팹 하나의 구성 (예시: 기존 타임라인 5개)
원칙 세 가지
  • 조각은 "무엇을", 표는 "언제". 조각은 자기가 짤인지 기믹인지 모른다. 같은 조각을 짤 표와 기믹 표 양쪽에 넣을 수 있다.
  • 프리팹 안의 것을 쓰면 컴포넌트, 값만 보면 SO. 패턴은 Director · 앵커 · 유물을 직접 가리켜야 해서 컴포넌트. 조건은 체력 · 전투 시간만 읽어서 SO (프로젝트의 EffectData와 같은 방식).
  • 상태는 컨테이너에. 조건 조각은 판정만 한다(IsMet). "이 기믹을 이미 썼나" · 쿨 · 직전 패턴은 컨테이너가 기억한다.

4. D6 — 조각을 어디서 자를까

1. 패턴 단위채택

조각 하나 = 패턴 하나 (내려찍기, 운석).

보스마다 다른 것 = 어떤 패턴을 갖고 있는가.

2. 단계 단위안 함

조각 하나 = 바라보기 · 재생 · 장판 · 대기.

타임라인과 AbilityData 이펙트가 이미 단계를 맡고 있어 순서를 정하는 곳이 세 군데가 된다.

3. 기능 단위조건만

조각 하나 = 선택 규칙 · 기믹 조건 · 이동.

바뀔 여지가 있는 건 기믹 조건뿐 (HP 줄 → 시간 · 광폭화).

5. 판단 순서 — BT

매 틱: 조건 확인 → BT 평가
엣지 케이스 — 시간 순서

6. 짤패턴 고르는 규칙 (선택기)

  1. 현재 짤 표
  2. 쿨 중인 조각 제외
  3. 직전 조각 제외 — 같은 패턴 연속 방지
  4. 남은 후보에서 가중치 추첨
  5. 후보가 0개면 → 직전 제외만 풀고 다시

7. 지금 코드에서 바뀌는 것

지금 (BossMonsterController)바뀐 뒤
_skills 타임라인 5개를 컨트롤러가 직접 보유패턴 조각 5개 (컴포넌트) + 짤 표 · 기믹 표
RandomNode + UseSkill(0~4) 하드코딩, 균등 무작위선택기: 가중치 · 직전 제외 · 쿨
패턴 수명이 세 곳에 흩어짐: _isActionRunning · _isSkillFiring · OnTimelineStopped실행기 하나: await pattern.Run(ctx, ct)
체력과 패턴이 무관조건 조각 → 기믹 대기열
중단 = 사망 때 타임라인 Stop취소 토큰 하나 (사망 때만 취소)

그대로 쓰는 것: 타임라인 에셋 5개 · 시그널 → CastAbility 경로 · ISummonRegistry 소환물 정리 · 입장 연출.

8. 실제 게임들은 어떻게 하나

사례구조이 기획과 비교
WoW 서버
SmartAI		공통 AI + DB 행. 한 행 = 이벤트(체력 % 등) + 페이즈 + 확률 + 행동기믹 표와 거의 같은 모양 — 공통 뼈대 + 데이터
WoW 서버
레이드 보스		보스마다 C++ 스크립트. 체력 % 확인 + 한 번만 발동 플래그반대 갈래 — 기믹이 복잡하면 보스별 코드로 간다
엘든 링보스별 전투 스크립트 + 공용 함수: 거리 구간별 가중치 추첨, 쿨이면 가중치 0선택기 규칙이 거의 같음
언리얼 GAS어빌리티를 조각처럼 부여, BT · StateTree가 고름"조각 끼워 맞추기"와 가장 가까움
로스트아크구현 방식은 공개 자료 없음동작(짤 + HP 줄 기믹)만 레퍼런스
이 기획의 자리 평범한 패턴은 데이터(TimelinePattern), 코드가 꼭 필요한 기믹만 전용 조각. 보스 전체를 스크립트로 만들지 않지만, 코드가 필요한 곳에서 막히지도 않는다 — 두 갈래의 중간.

9. 구현 순서

1단계는 동작을 지금과 같게(무작위 5개) 두고 패턴 실행 부분만 바꾼다. 각 단계는 플레이로 확인할 수 있는 크기.

범위 밖: 기믹 성공/실패 분기(무력화 → 그로기, 실패 → 전멸기) · 추적 · 어그로/다중 대상 · HP 바 줄 표시 UI.
