# 보스 패턴 구조 개편 — 초안

> 상태: **초안 (2026-10-18)** · 결정되지 않은 항목은 "결정 대기"로 표시
> 레퍼런스: 로스트아크 레이드 (짤패턴 + HP 줄 기믹)

---

## 1. 출발점

로스트아크 레이드의 보스를 레퍼런스로 가정한다.

- 평소에는 **짤패턴** 여러 개를 섞어서 수행한다.
- 체력이 **정해진 줄 수**에 도달하면 **정해진 패턴(기믹)**을 수행한다.
- 기믹을 지나면 패턴 구성이 바뀌기도 한다(강화 패턴, 페이즈).

이 구조를 지금 보스에 넣으려고 하면 **현재 구조로는 표현할 자리가 없다.** 그래서 질문은 이것이다.

> **"짤패턴 + HP 줄 기믹"을 표현하려면 보스 패턴 구조를 어떻게 개편해야 하는가?**

---

## 2. 현재 구조

대상: `Assets/Scripts/Controllers/Monster/Boss/BossMonsterController.cs`, `Controllers/Monster/BTNode.cs`

### 2-1. 행동 트리

```
Selector
├─ Sequence: 사망 확인 → 사망 처리
└─ BossSequence (진행 위치를 기억하는 시퀀스)
   ├─ 입장 연출이 끝났는가
   ├─ RandomNode: UseSkill(0) ~ UseSkill(4) 중 하나   ← 균등 무작위
   └─ WaitNode(_patternInterval = 2초)
```

- 스킬 = 타임라인 5개 (`Resources/Timelines/BossTimeline/`: `Boss_Normal_Attack`, `Boss_Skill_01~04`)
- `UseSkill(i)`가 `PlayableDirector`에 해당 타임라인을 꽂아 재생하고, 타임라인이 끝나면 `OnTimelineStopped`가 상태를 되돌린다.

### 2-2. 패턴 실행 상태

패턴 하나의 수명이 **세 곳에 흩어져** 있다.

| 무엇 | 어디 |
|---|---|
| "지금 패턴이 돌고 있다" | `_isActionRunning` |
| "방금 패턴이 끝났다 → 다음 평가에서 Success 반환" | `_isSkillFiring` |
| 패턴 종료 시점 | `PlayableDirector.stopped` 콜백 (`OnTimelineStopped`) |

`UseSkill`은 매 프레임 불리면서 두 플래그로 "처음 진입 / 진행 중 / 방금 끝남"을 구분한다. 일반 몬스터와 같은 냄새(BT 안에 상태 플래그가 숨어 있는 구조)다.

### 2-3. 이미 잘 되어 있는 것 (유지)

- **연출의 데이터화:** 패턴 내용은 타임라인 에셋이라 코드 수정 없이 바꿀 수 있다.
- **소환물 관리:** `ISummonRegistry`로 소환물을 등록하고, 사망 시 함께 정리한다.
- **사망 시 정리:** 진행 중인 타임라인을 멈추고 플래그를 리셋한다.
- **진행 위치를 기억하는 시퀀스:** `BossSequence`는 매 틱 처음부터 돌지 않는다.

## 3. 문제

1. **선택에 기억이 없다.**
   `RandomNode`가 매번 `Random.Range(0, 5)`로 고른다. 직전에 무엇을 했는지 모른다.
   - 직전과 같은 패턴이 나올 확률 20%
   - 같은 패턴 3연속 4%
2. **HP를 보고 패턴을 고르는 경로가 없다.**
   최상위가 "사망 / 무작위 패턴" 두 갈래뿐이다. HP 줄 기믹을 끼워 넣을 자리가 없다.
3. **패턴을 중간에 끊는 방법이 정의되어 있지 않다.**
   중단은 사망할 때만 처리된다. "기믹 진입을 위해 짤패턴을 끊는다"는 개념이 없다.
4. **선택 규칙이 코드에 박혀 있다.**
   패턴을 추가하거나 비중을 바꾸려면 `ConstructBehaviorTree`의 `UseSkill(n)` 목록을 고쳐야 한다. 가중치·조건·쿨다운을 표현할 데이터가 없다.
5. **페이즈 개념이 없다.**
   전투 내내 같은 5개 풀이다.

## 4. 요구사항 (레퍼런스에서 도출)

| # | 요구사항 | 내용 |
|---|---|---|
| R1 | 짤패턴 선택 규칙 | 가중치 · 직전 반복 금지 또는 패턴별 쿨다운 · 조건(근거리용/원거리용 등) |
| R2 | HP 임계 기믹 | 정해진 HP 줄(또는 비율)에 도달하면 정해진 패턴을 **한 번** 수행 |
| R3 | 우선순위와 중단 | 임계 도달 시 진행 중인 짤패턴을 즉시 끊을지, 끝나고 들어갈지. 패턴별로 "끊을 수 있음" 지정 |
| R4 | 페이즈 | 기믹 이후 짤패턴 풀이 바뀐다 |
| R5 | 데이터로 구성 | 보스 하나의 패턴 구성을 코드 수정 없이 데이터로 바꿀 수 있다 |

## 5. 설계 초안

### 5-1. 역할 분리

| 역할 | 책임 | 지금 대응하는 코드 |
|---|---|---|
| **결정 (BT)** | "지금 무엇을 해야 하나"만 판단: 사망 > 대기 중인 기믹 > 짤패턴 | `ConstructBehaviorTree` |
| **선택기** | 짤패턴 풀에서 하나 고르기 | `RandomNode` |
| **실행기** | 패턴 하나의 수명(시작 → 진행 → 종료/중단) 단일 책임 | `UseSkill` + 두 플래그 + `OnTimelineStopped` |
| **HP 감시** | HP 변화를 보고 임계 통과를 기록, 기믹을 대기열에 올림 | 없음 |

핵심은 **BT는 결정만, 실행은 실행기**다. 흩어진 두 플래그와 콜백이 실행기 하나로 모인다.
DX11 프로젝트의 "FSM → BT 전환" 다음 단계로 이어진다. BT가 결정을 맡고, 실행 수명은 상태를 가진 객체가 맡는다.

### 5-2. 데이터 (초안)

```
BossPatternData (패턴 하나)
  - Timeline            : 연출 (기존 타임라인 에셋 재사용)
  - Weight              : 짤패턴 추첨 가중치
  - Cooldown            : 다시 뽑히기까지 최소 시간 (또는 최소 간격 패턴 수)
  - NoRepeat            : 직전 패턴과 같으면 제외
  - Condition           : 사거리 등 사용 조건 (없으면 항상)
  - Interruptible       : 기믹 진입 시 끊을 수 있는가

BossPhaseData (페이즈 하나)
  - FillerPatterns      : 짤패턴 풀
  - Interval            : 패턴 사이 대기

BossHpTrigger (HP 임계 하나)
  - Threshold           : HP 줄 수 또는 비율
  - GimmickPattern      : 수행할 패턴
  - EntryPolicy         : 즉시 / 현재 패턴 후
  - LockHp              : 기믹이 끝날 때까지 HP를 임계에 고정할지
  - NextPhase           : 기믹 후 넘어갈 페이즈 (없으면 유지)

BossPatternSet (보스 하나)
  - Phases[]
  - HpTriggers[]        : 임계 높은 순
```

### 5-3. 흐름

```
매 틱
  1) 사망?                         → 사망 처리 (실행 중 패턴 중단 + 정리)
  2) 대기 중인 기믹이 있다?
       - 실행 중 패턴이 Interruptible  → 중단 후 기믹 시작
       - 아니면                        → 현재 패턴 종료를 기다림
  3) 실행 중 패턴이 있다?           → 계속
  4) 대기 간격이 남았다?            → 대기
  5) 선택기로 짤패턴 하나 → 실행기에 시작 요청

HP가 바뀔 때 (Health.OnHpChanged)
  - 새로 통과한 임계를 대기열에 올림
  - LockHp 임계면 HP를 임계 값 아래로 내려가지 않게 고정

기믹 패턴 종료 시
  - HP 잠금 해제
  - NextPhase가 있으면 페이즈 교체
```

### 5-4. 선택기 규칙 (초안)

1. 현재 페이즈의 짤패턴 풀
2. `Condition`을 만족하지 않는 패턴 제외
3. 쿨다운 중이거나 `NoRepeat`에 걸리는 패턴 제외
4. 남은 후보에서 가중치 추첨
5. 후보가 0개 → 대체 규칙 (결정 대기 D3)

## 8. 포트폴리오 서사 (초안)

1. **목표:** 로스트아크식 레이드 보스 (짤패턴 + HP 줄 기믹)
2. **문제:** 지금 구조는 기억 없는 균등 무작위 → 같은 패턴 반복, HP 기믹 불가, 패턴 중단 개념 없음
3. **원인:** 결정(무엇을 할까)과 실행(패턴 수명)이 BT 노드와 플래그에 섞여 있음
4. **개편:** BT = 결정 / 실행기 = 수명 / 선택기 = 규칙 / HP 감시 = 임계, 그리고 데이터로 구성
5. **결정:** HP 잠금 vs 대기열, 후보 0개, 중단 정책 같은 엣지 케이스 판단과 이유
6. **데모:** 반복 없는 짤패턴 · HP 줄 도달 시 기믹 진입 · 페이즈 전환

DX11 프로젝트의 FSM → BT 쪽(덱 36~38쪽)과 "1부: 구조 전환 / 2부: 결정과 실행의 분리"로 이어진다.
